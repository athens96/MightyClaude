# Windows 기능 대응 목록

macOS 코드베이스에서 발견한 모든 기능 영역과 Windows 구현 현황.

최종 검증: `4301339`의 Windows x64·ARM64 Core·빌드·네이티브 GUI 검사가 모두 통과했고, 배포 ZIP과 화면 자료를 업로드했다. [검증 기록과 다운로드 안내](windows-port-verification.md)에 통과 범위·OS 차이·실기 미확인 항목을 정리했다. 아래 개별 행의 과거 커밋·CI 대기 문구는 구현 이력이며 최신 자동 검사 결과는 이 기록을 따른다. 물리 입력기·실제 계정·기기의 미확인 표시는 계속 유효하다.

2026-10-04 소스 대조: 아래 표의 **코드 구현**은 현재 작업 트리에서 실행 경로가 연결됐다는 뜻이다. **Core 검증**은 macOS 호스트에서 C# 테스트를 실행한 결과이며 Windows 화면 검증과 구분한다. WinUI C# 교차 컴파일은 API·타입 검증용으로, Windows 전용 XAML 생성·패키징·ConPTY·IME·WebView2의 실제 실행을 증명하지 않는다. 새 코드의 Windows 기기 점검은 [화면 체크리스트](windows-screen-checklist.md)를 따른다. 기존 커밋의 CI 통과 표시는 해당 커밋에만 적용된다.

단계 셀은 `1단계 | 터미널 | 2단계 | 3단계 | 이미 있음 | Windows에 해당 없음 | 배포 인프라` 중 하나.
'확인 필요' 표시는 단계가 판단으로 결정된 행. '보류'는 macOS와의 차이를 사용자가 정해야 하는 행 ('확인 필요'와 다른 표시).
문구 규칙(v4부터): 설정 화면과 안내 패널의 문구는 두 앱이 같은 키로 `locales/ko.json`·`locales/en.json`을 읽는다. 아직 옮기지 않은 문구는 종전대로 macOS 리터럴과 같아야 하며, 남은 수는 `node scripts/check-locales.js`가 센다(`docs/i18n.md`).

## 마지막 기능 대조에서 보완한 동작

- 다음 작업 제안: `NextActions.cs`가 Mac·모바일과 같은 `next-actions.json` 사례를 읽는다. `MainWindow.NextActions.cs`의 버튼은 현재 초안 뒤에 제안을 한 번의 네이티브 편집으로 붙이며 자동 전송하지 않는다. 실행 중이거나 새 사용자 메시지가 생긴 경우 이전 제안은 무효가 된다. Core 공유 사례·초안 보존 검사 통과; 실제 버튼 UIA 검사는 새 Windows CI 대상이다.
- 모바일 연결 설정: 재연결은 소켓을 다시 만들면서 연결 키와 신뢰 기기를 유지한다. 호스트 ID·연결 키의 표시/숨김을 제공하고 설정을 닫으면 표시 중인 키를 지운다. 기기 해제는 현재 Mac과 같이 연결 키를 교체하고 모든 신뢰 기기를 해제하되 오래된 기기 ID의 중복 해제는 키를 다시 바꾸지 않는다.
- 화면 공유 설정: 개별 세션 종료는 선택한 피어만 정리한다. 제어 키 삭제는 확인 창을 거치며 확인하는 동안 기기나 키가 바뀌면 적용하지 않는다. 암호화 로컬 릴레이의 재연결과 선택한 화면 세션만 종료하는 Core 검사를 추가했다. 실제 휴대폰 연결·화면 조작은 별도 실기 항목이다.
