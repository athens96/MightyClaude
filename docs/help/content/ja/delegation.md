Mightyオーケストレーションでは、Claudeのペイン(親)が作業を分けて、ほかのClaudeのペイン(子)に任せます。子はそれぞれ自分のgit worktreeで作業し、終わるとレポートを残します。親は通知を受け取ってレポートを読み、結果をマージするかどうかを決めます。MacアプリとWindowsアプリで使えます。Macでは、実行中のClaudeペインの入力欄から子を自分で起動することもできます([新しいworktreeで実行する](#worktree))。 以前の名前はエージェント委任です。

> [!warning]
> 実験的な機能です。Macでは初期状態でオンで、設定でオフにできます。Windowsでは初期状態でオフで、設定画面もありません。まずは練習用のリポジトリで試してください。

## オンとオフ {#enable}
{{platform:mac}} オフにしない限りオンです。設定の{{ui:settings.nav.general}}タブで{{ui:settings.delegation.toggle}}を切り替えます。アプリを開き直さなくても、次に始まる実行から反映されます。同じスイッチがdefaultsキー`delegation.enabled`なので、ターミナルで次のコマンドを実行してもオフにでき、`defaults delete dev.mightyclaude.native delegation.enabled`でオンに戻ります:

```sh
defaults write dev.mightyclaude.native delegation.enabled -bool false
```

{{platform:mac}} 以前のバージョンはこのキーを設定したときだけオンになり、オフにするには`defaults delete …`を使っていました。今はそうするとオンのままになるので、オフのままにするには設定で{{ui:settings.delegation.toggle}}をオフにしてください。

{{platform:windows}} 初期状態ではオフです。アプリを終了した状態でコマンドプロンプトまたはPowerShellで次のコマンドを実行し、アプリをもう一度開きます:

```
reg add "HKCU\Software\MightyClaudeNative" /v delegation.enabled /t REG_DWORD /d 1 /f
```

Windowsでは、`HKEY_CURRENT_USER\Software\MightyClaudeNative`の下の`delegation.enabled`の値(REG_DWORD)が0以外ならオンです。値がないか0ならオフです。

- オンにすると、Claudeのペインで新しい実行を始めるたびに委任ツールが付きます。すでに動いている実行には付きません。
- 親が使うツールは`delegate`(任せる)、`list_children`(子の一覧)、`child_status`(状態とレポート)、`merge`(マージ)、`follow_up`(追加の指示)です。`discard`(破棄)は親には使えず、子のカードからあなただけが行えます。
- Windowsでオフにするには、`reg delete "HKCU\Software\MightyClaudeNative" /v delegation.enabled /f`を実行し、アプリをもう一度開きます。外れるのはツールだけで(Macでは{{kbd:⌘Enter}}が再び実行中のClaudeにすぐ送信します)、既存の子ペイン、カード、後片付けはそのまま動きます。

## 作業を任せる {#delegate}
1. gitリポジトリのフォルダーをワークスペースとして開き、Claudeのペインを開きます。このペインが親です。
2. 「delegateツールでMightyの子ペインを二つ開いて、この作業を分けて任せて」のように、ツール名を入れて頼みます。「分けてやって」とだけ言うと、Claudeが自分の中のサブエージェントで済ませることがあります。
3. 子ペインは親の隣に開き、サイドバーでは親の下に一段下げて表示されます。

![[delegation-tree]]

- 子ごとにブランチ`mighty/<子のid>`とworktree(Macは`~/.mightyclaude/worktrees/<子のid>`、Windowsは`%USERPROFILE%\.mightyclaude\worktrees\<子のid>`)ができます。worktreeはプロジェクトフォルダーの外にあるので、親の作業には触れません。
- 子は親の最後のコミットから始まります。親のフォルダーでまだコミットしていない変更は、子には渡りません。
- 任せた作業はTASK.mdに、結果はREPORT.mdに書かれます。どちらもworktree内のgitが無視するフォルダーにあり、コミットされません。
- 子は親が選んだ権限モードで始まり、そのモードは親のペイン自身のモードより広くできません。広げられるのはあなただけで、実行と実行の合間に、子ペインの入力欄の権限メニューかスマートフォンの設定から行います。
- 親は子の承認カードに答えられません。子ペインにカードが出たら、そのペインであなたが答えてください。
- 一つの親が`delegate`ツールで開いておける子は3つまでで(Macでは、これとは別に自分で起動した子を3つまで持てます。[新しいworktreeで実行する](#worktree)を参照)、子はさらに委任できません。レポート済みやマージ済みの子も、ペインが開いていれば数に入るので、終わった子ペインを閉じると空きができます。ディスクの空きが10 GB未満だと委任は断られます。

## 新しいworktreeで実行する {#worktree}
{{platform:mac}} 子を自分で起動することもできます。Claudeペインの実行中にリクエストを書き、{{kbd:⌘Enter}}を押すか、停止ボタンの横にある丸い{{ui:queue.worktree}}ボタン(ブランチのアイコン)を押します。実行中のタスクはそのまま続き、リクエストは専用のworktreeを持つ新しい子ペインですぐに実行されます。新しい子ペインはサイドバーでそのペインの下に表示されます。その間に親ペインで入力を始めていなければ、新しいペインがすぐに画面に出ます。

- {{kbd:⌘Enter}}が新しいworktreeを使うのは、worktreeを作れる場所だけです。コミットのあるブランチをチェックアウトしたgitリポジトリである必要があります。それ以外の場所(gitリポジトリでない、まだコミットがない、ブランチではなくコミットをチェックアウトしている)では、これまでどおり実行中のClaudeにすぐ送信します。
- 親の`delegate`と同じ方法で作られます。親の最新のコミットからブランチ`mighty/<子のid>`を作り、worktreeはプロジェクトの外に置き、ディスクの空きが10GB必要です。自分で起動して開いている子は1つのペインにつき3つまでで、`delegate`が作れる3つとは別に数えます。どちらも相手を妨げません。
- 親ペインの権限モードで、親ペインのモデルと{{ui:composer.effort.label}}で実行します。すべてのリクエストをプランモードで始めるスタイルでは、プランモードで始まります。添付ファイルも一緒に渡ります。
- 最初のメッセージはあなたのテキストで、その後にアプリが、子がどこで作業するかを伝え、終わったらコミットしてREPORT.mdを書くよう添えます。そうするとカードからマージできます。スラッシュコマンド(`/`で始まるテキスト)は入力したとおり単独で実行され、アプリの案内は子の次のリクエストとして続くため、コマンドの引数になりません。
- 自分で起動した子について、親は通知を受け取りません。親が頼んだ作業ではないからです。親のツールもこの子を一覧に出さず、マージも追加の指示もできません(`human_started`)。サイドバーで状態を確かめ、カードの{{ui:delegation.card.merge}}と{{ui:delegation.card.discard}}ボタンを自分で使ってください。
- 子を作れないとき、または作った後で起動できなかったとき(自分で起動して開いている子がすでに3つある、ディスクが足りない、worktreeや最初の実行が失敗したなど)は、ペインの会話に理由が残ります。そのとき、実行中のClaudeが受け取れるなら(添付ファイルなし)テキストはそちらにすぐ送信され、そうでなければ{{kbd:Enter}}を押したときと同じようにそのペインの次のリクエストになります。キューがいっぱいなら入力欄に戻ります。起動できなかった子は、カードから破棄するまで一覧に残ります。
- 子ペインやMightyオーケストレーションをオフにしたペインでは、{{kbd:⌘Enter}}はこれまでどおり実行中のClaudeにすぐ送信し、CodexとAntigravityのペインは引き続きキューに入れます。スマートフォンの送信方法は変わらず、スマートフォンからすぐ送信すると今までどおり実行中のClaudeに届きます。

## 子の状態 {#states}
サイドバーに子ごとの状態が表示されます。

| 状態 | 意味 |
|---|---|
| {{ui:delegation.child.state.creating}} | worktreeとペインを作っています。 |
| {{ui:delegation.child.state.running}} | 作業しています。 |
| {{ui:delegation.child.state.waiting}} | 承認や質問へのあなたの答えを待っています。 |
| {{ui:delegation.child.state.reported}} | REPORT.mdを残して実行を終えました。 |
| {{ui:delegation.child.state.merged}} | 親のブランチにマージされました。 |
| {{ui:delegation.child.state.ended}} | 新しいレポートなしで実行が終わりました。 |
| {{ui:delegation.child.state.interrupted}} | アプリを終了したため、実行が途切れました。 |
| {{ui:delegation.child.state.failed}} | 子ペインを開始できませんでした。 |
| {{ui:delegation.child.state.closed}} | ペインが閉じられました。破棄するまで一覧に残ります。 |

子が新しい実行を始めると{{ui:delegation.child.state.reported}}の状態は外れ、次のレポートには次のレポート番号が付きます。

## 通知と保留 {#notices}
子がレポートしたときと、開始できなかったときに、親へ通知が一度届きます。親が始めた実行(最初に任せた作業や追加の指示)がレポートなしで終わったときにも届きます。通知は`[Mighty Claude notice …]`で始まる短い案内にすぎず、レポートの中身は親が`child_status`で読みます。

- 親が実行中なら、通知はその実行にそのまま届きます。
- 親がアプリを開いたあとに前の実行を正常に終えて待機しているなら、通知が次の実行を始めます。
- それ以外では通知は保留されます。停止のあと、エラーのあと、アプリを開き直したあと、CLIの更新中などです。すでに保留された項目があると、新しい通知もその後ろに保留され、順番が守られます。

保留された通知は、親の入力欄の上にあるキューのいちばん上に、ピンの印が付いた行として表示されます。この行には削除ボタンがなく、ふつうのキューのリクエストと違って、停止してもアプリを開き直しても残ります。

![[delegation-held]]

- 次に何かを送ると、保留された項目がすべて、古い順に、あなたの文より前に付いて一つの実行で届きます。
- {{ui:queue.runNext}}ボタンを押すと、保留された項目だけを一つの実行で送ります。
- 通知はアプリを開き直しても、ちょうど一度だけ届きます。保留された行はスマートフォンのキューにも表示され、スマートフォンから送っても一緒に届きます。

## 追加の指示 {#follow-up}
親は`follow_up`ツールで、一つの子に追加の指示を2回まで送れます。追加の指示は通知と同じ決まりで子ペインに届き、一つあたり48 KiBまでです。

## マージ {#merge}
子の結果を親のブランチに取り込む方法は二つあります。

1. **親の`merge`ツール**は早送り(fast-forward)だけを行います。親は`child_status`で得た子のheadを一緒に渡します。子がまだレポートしていない、子か親のフォルダーにコミットしていない変更がある、子のheadが動いた、親のブランチがその間に先へ進んだ(分岐)、または親のブランチがチェックアウトされていない場合は断られ、何も変わりません。このツールで承認カードが出るかどうかは、親のペインの権限モードによります。
2. **カードの{{ui:delegation.card.merge}}ボタン**はあなたが押します。早送りできればそうし、できなければマージコミットをちょうど一つ作ります。先に衝突を調べ、断ったときは理由をカードに表示します。
   マージが通ると、その子をすぐ破棄するかを尋ねます。{{ui:delegation.mergedDiscard.confirm}}を選ぶと子ペインを閉じ、worktreeとブランチを削除します。マージした内容は親ブランチに残りますが、そのマージは取り消せなくなります。{{ui:delegation.mergedDiscard.later}}を選ぶとカードはそのまま残ります。

> [!tip]
> 子を一つマージすると親のブランチが先へ進むので、残りの子はふつう`merge`ツールで分岐として断られます。そのときはカードの{{ui:delegation.card.merge}}ボタンでマージしてください。

マージしたあと、子が新しい実行を始めるまでは、ペインを閉じてもカードに{{ui:delegation.card.undo}}ボタンが残ります。親のブランチがそのマージのまま、親のペインが待機中で、コミットしていない変更がないときだけ使えます。取り消すと、ファイルはマージ前の状態に戻り、ペインが開いている子はもう一度{{ui:delegation.child.state.reported}}になります。

> [!note]
> マージはできたのに委任の記録を保存できなかったときは、カードがそう知らせます。マージはそのままで、記録は次の保存で書き直されます。

## 破棄 {#discard}
カードの{{ui:delegation.card.discard}}ボタンは、子のworktreeとブランチを、まだマージしていない作業ごと削除します。破棄できるのはあなただけで、親にはできません。

- 確認ウィンドウ({{ui:delegation.discard.title}})は、子のworktreeの中に入っていて一緒に削除されるほかのworktreeをすべて示します。
- その一覧を確認できないときは、確認ウィンドウに破棄ボタンは出ず、何も止めたり削除したりしません。

> [!tip]
> アプリがまだマージしていない作業を勝手に消すことはありません。マージしていない作業が消えるのは、あなたが確認した破棄のときだけです。

## ペインを閉じる・後片付け {#close}
- **マージ済みの子ペインを閉じると**、作業がすべてマージ済みで未コミットの変更が残っていなければ、アプリがworktreeとブランチを片付けます(`git branch -d`、強制削除はしません)。条件に合わなければペインだけが閉じ、worktreeは残ります。
- **マージする前に子ペインを閉じると**、アプリではもうマージできません。カードには破棄だけが残り、ブランチとworktreeは破棄するまでそのまま残ります。
- **開いている子がある親のペインを閉じると**、デスクトップアプリはまず確認します({{ui:delegation.parentClose.title}})。閉じるのは親のペインだけで、子は作業を続けます。
- 親ペインが閉じられた子は、サイドバーの{{ui:delegation.tree.parentClosed}}の項目の下にカードとして残ります。その子の通知はカードに保留されて件数が表示され、追加の指示はもう受け取りません。
- 開いている子がある、または片付けていない子のworktreeが残っているワークスペースは削除できません。
- {{platform:windows}} 子のworktreeの中にジャンクションやシンボリックリンク(リンクで作った`node_modules`など)があると、マージ済みの子ペインを閉じてもアプリはworktreeを片付けずに残します。リンクをたどってリンク先のフォルダーまで消してしまわないためです。この場合はカードの{{ui:delegation.card.discard}}ボタンで削除します。破棄はリンクそのものだけを先に外し、リンク先のフォルダーには触れません。

## 上限と対応範囲 {#limits}
| 項目 | 上限 |
|---|---|
| 一つの親が開いておける子 | `delegate`で3つ、自分で起動して3つ(Mac) |
| 委任の深さ | 一段(子はさらに委任できない) |
| 一つの子への追加の指示 | 2回、一つあたり48 KiBまで |
| 任せる作業(TASK.md) | 64 KiB |
| 必要なディスクの空き | 10 GB |

- 親も子もClaudeのペインである必要があります。CodexとAntigravity(Gemini)のペインは委任しません。
- Macアプリは初期状態でオンで、設定にスイッチがあります。Windowsアプリは隠しスイッチでオンにします([オンとオフ](#enable))。スマートフォンに新しい画面はありませんが、保留された行はスマートフォンのキューにも表示されます。
