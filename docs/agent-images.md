# 에이전트가 보여 준 그림 (Mac)

에이전트가 작업 중에 그림을 보여 주면(이미지 파일을 읽거나, 브라우저 스크린샷을 찍거나, 답변에 Markdown 그림을 넣으면) 기본 화면의 대화 기록에 그 그림이 나온 자리에 그대로 표시된다. 마이티 모드에서는 같은 그림이 블록 안의 대화 표시에도 나오고, 단계 옆의 **그림 미리보기** 블록에 모인다([docs/mighty-mode.md](mighty-mode.md#그림-미리보기-블록)).

## 표시

- 그림은 썸네일로 나온다: 가로 최대 480pt(세로 최대 640pt), 비율 유지, 둥근 모서리와 가는 테두리. 창이 좁으면 줄 너비에 맞춰 줄어든다. 도구 결과의 그림 아래에는 출처(도구 이름과 요약, 예: `Read · /path/shot.png`)가 작게 붙는다.
- 그림을 누르면 큰 창에서 창에 맞춰 보여 준다(긴 변 최대 4,096 픽셀로 다시 디코딩). 창에도 복사·Finder·미리보기 버튼이 있다.
- 그림을 우클릭하면 **크게 보기 · 그림 복사 · Finder에서 보기 · 미리보기에서 열기**가 메뉴 맨 위에 붙는다. Finder는 에이전트가 읽은 원본 파일이 있으면 그것을, 없으면 캐시 파일을 보여 준다.
- 불러오는 동안은 같은 비율의 자리 표시가 나온다. 캐시에서 지워졌거나 원본 파일이 사라진 그림은 `그림을 더 이상 찾을 수 없음` 자리 표시로 남는다.

## 그림의 출처

| 출처 | 신호 | 비고 |
|---|---|---|
| Claude 도구 결과 | `user` 프레임 `tool_result.content[]`의 `{"type":"image","source":{"type":"base64","media_type",…,"data"}}` | `Read`로 이미지 파일을 읽은 경우, MCP 도구(Playwright·브라우저 스크린샷 등)의 그림 결과. 같은 줄의 `tool_use_result` 사본은 읽지 않는다. 하위 에이전트(`parent_tool_use_id`)의 그림은 그 에이전트 블록에만 들어가고 기본 대화에는 나오지 않는다. |
| Claude 메시지 | `assistant` 프레임 `content[]`의 `image` 블록 | 드물다. 같은 방식으로 처리한다. |
| Codex MCP 결과 | `mcp_tool_call` 항목 `result.content[]`의 `{"type":"image","data","mimeType"}` | `codex exec --json`과 앱 서버(`mcpToolCall`) 모두. |
| Codex `image_view` | 앱 서버 `imageView {id, path}` → `image_view` | 경로만 오므로 아래의 경로 규칙을 통과한 파일만 읽는다. 통과하지 못하면 시스템 줄 하나로 알린다. 0.159 바이너리에서 찾은 `codex exec --json` 항목 이름(agent_message·reasoning·command_execution·file_change·mcp_tool_call·web_search·todo_list)에는 없어 사실상 승인 요청 모드(앱 서버) 실행에서만 나온다. exec가 같은 이름으로 내보내면 그대로 받는다. |
| Codex `image_generation` | 앱 서버 `imageGeneration {result, savedPath}` → `image_generation` (exec도 같은 이름이면) | `result`가 base64 그림이면 그것을, 아니면 `savedPath`를 경로 규칙으로 읽는다. |
| Markdown 그림 | 답변의 `![대체 문자](대상)` | 아래 경로 규칙을 통과한 파일과 `data:image/…;base64,` URI만 그린다. |

사용자가 요청에 붙인 첨부 그림의 되울림은 다시 표시하지 않는다(`tool_result`와 `assistant` 블록만 읽는다). Gemini는 그림을 보내지 않는다.

## 안전 규칙

- **경로 규칙** (Markdown 그림, Codex `image_view`·`savedPath`): 그림 확장자(png·jpg·jpeg·gif·webp·heic·heif·tif·tiff·bmp·svg)를 가진 일반 파일이고, 심볼릭 링크를 모두 풀어낸 실제 경로가 **작업 폴더** 또는 **시스템 임시 폴더**(`$TMPDIR`, `/tmp`) 안에 있어야 한다. 상대 경로는 작업 폴더 기준으로만 해석한다. `..`·심볼릭 링크로 밖을 가리키거나, `~`로 시작하거나, 없는 파일이면 그리지 않고 대체 문자 옆에 `(작업 폴더나 임시 폴더 밖의 그림은 표시하지 않음)`을 붙인다. 읽기는 파일 창과 같은 안전 열기(`WorkspaceFiles.openResolved`: 마지막 심볼릭 링크를 따르지 않고, 일반 파일만, 열린 디스크립터의 실제 경로를 다시 확인)를 쓴다.
- **원격 그림은 자동으로 불러오지 않는다**: `http(s)://` 그림은 대체 문자를 링크로 보여 주고 `(외부 그림 · 자동으로 불러오지 않음)`을 붙인다. 누르면 기본 브라우저로 연다. 파일 창의 규칙과 같다.
- 모든 그림은 디코딩 전에 다시 검사한다(`AgentImageSupport.inspect`): 20 MB 이하, ImageIO가 실제로 읽는 비트맵(png·jpeg·gif·webp·heic·heif·tiff·bmp, 선언한 형식이 아니라 실제 형식으로 저장), 픽셀 수 6,400만 이하이고 긴 변 8,000 픽셀 이하(파일 창의 디코딩 상한 2억 5천만보다 훨씬 낮다). SVG는 앞머리(XML 선언·주석·doctype) 다음 첫 요소가 `<svg`인 문서이고 바깥 파일·주소를 참조하지 않을 때만 받는다(`FilePreviewClassifier.svgLoadsExternalContent`). PDF와 그 밖의 형식은 받지 않는다. 거절한 그림은 시스템 줄 하나로 알린다.
- 디코딩과 썸네일 생성(ImageIO, 긴 변 최대 960 픽셀 = 480pt의 2배)은 메인 스레드 밖에서 한 번에 두 장까지 한다. SVG도 이때 한 번 비트맵으로 그려 두고, 화면은 벡터를 다시 그리지 않는다.
- 썸네일은 메모리 캐시(192 MB, 가장 오래 그리지 않은 것부터 비움)에만 있고, 대화 기록의 그림 칸은 그림의 키만 가진 채 그릴 때마다 캐시에서 꺼낸다. 함께 끝난 불러오기는 50 ms 안에서 한 번에 알리고, 대화 기록은 그 그림 칸만 다시 배치·표시한다. 파일 그림의 키에는 파일 크기와 수정 시각이 들어가 같은 이름의 파일이 바뀌면 다시 읽고, 실행이 끝나면 읽지 못했던 파일 그림을 다시 시도한다.
- Markdown 그림의 절대 경로는 퍼센트 인코딩을 풀어 둔다(`/tmp/스크린샷 2026-10-01 오전 9.40.12.png`처럼 한글·공백이 든 이름).

## 저장과 한도

- 도구가 보낸 base64는 실행기에서 바로 풀어(큰 줄은 모든 창이 함께 쓰는 실행기 액터 밖에서 줄을 자르고 JSON을 읽을 때 함께 풀고 해시를 내어 쓴다) 앱 데이터 폴더의 **그림 캐시**(`~/Library/Application Support/MightyClaude Native/image-cache/<sha256>.<확장자>`)에 한 번만 쓴다. 대화 기록·그래프 기록·저장 상태에는 참조만 남는다: `kind: "image"` 항목의 `images: [{hash, mediaType, width, height, bytes, source, path?}]`와, 그림이 없는 화면을 위한 `text`(`그림 · Read · …`).
- 한도: 그림 하나 20 MB, 항목 하나 16장, 요청(실행) 하나 64장(넘으면 한 번 알리고 이후 그림은 건너뜀), 캐시 전체 200 MB. 캐시가 넘치면 가장 오래 쓰지 않은 그림부터 지운다(그림을 그릴 때마다 사용 시각을 갱신). 캐시 파일은 이름의 해시와 내용이 맞을 때만 쓰고, 같은 그림을 다시 받았을 때 파일 크기나 해시가 맞지 않으면 다시 쓴다.
- 다시 연 세션은 캐시에 파일이 남아 있으면 그림을 그대로 보여 주고, 없으면 `그림을 더 이상 찾을 수 없음`을 표시한다.
- 그림이 실린 stream-json 한 줄을 받을 수 있도록 실행기의 한 줄 상한을 64 MiB로, Codex 승인 채널의 프레임 상한을 32 MiB로 올렸다. 그림을 싣지 않는 Gemini는 8 MiB다. 줄 나누기는 `memchr`로 줄바꿈을 찾아 덩어리째 붙이고, 끝난 줄은 버퍼째 넘겨 큰 줄의 메모리를 붙잡지 않는다. 실행기는 읽었지만 줄 나누기에 아직 넘기지 못한 출력이 실행마다 4 MB를 넘으면 파이프 읽기를 멈추고 기다린다(자식은 가득 찬 파이프에서 기다린다). 줄 나누기가 붙잡고 있는 끝나지 않은 줄은 그 4 MB에 들지 않고, 모든 실행이 함께 쓰는 256 MB 한도로 센다. 한도를 넘으면 가장 큰 줄을 가진 실행만 계속 읽어 그 줄을 끝내고(또는 상한에서 자르고), 줄을 붙잡은 다른 실행의 읽기는 기다린다. 그래서 큰 줄도 조각을 잃지 않으며, 전체는 대략 256 MB에 진행 중인 한 줄과 실행마다 4 MB를 더한 만큼으로 묶인다. 끝난 줄을 파싱한 JSON 값은 넘겨질 때까지 잠깐만 산다.

## 휴대폰

휴대폰 계약에는 그림이 없다. 대화 항목을 보낼 때 `image` 항목은 `system` 항목으로 바꾸고 `images`를 지운다(`MobileRemoteSupport.phoneEntries`). 휴대폰에는 `그림 · Read · …` 같은 한 줄만 가고, 그림 바이트나 캐시 이름은 중계 서버를 지나지 않는다. 휴대폰 앱은 바뀌지 않았다.

## 확인

`AgentImagePipelineTests`가 실제 자식 프로세스가 내보내는 약 30 MB 스크린샷 줄과 그 뒤의 줄이 느린 소비자에서도 온전히 도착하고 그림이 캐시에 남는지, 줄 나누기, 미리 푼 그림 표식, 긴 비 JSON 줄을 확인한다. `AgentImageTests`(MightyCore)가 stream-json 고정 입력(Claude `Read`·MCP 스크린샷·하위 에이전트, Codex MCP·`image_view`·`image_generation`), 1 MiB를 넘는 그림 줄, Markdown 추출과 경로 규칙(작업 폴더·임시 폴더 허용, 밖·`..`·심볼릭 링크·`~` 거절, http는 링크만), 캐시 쓰기·읽기·LRU 정리·변조 거부와 다시 쓰기, 크기·픽셀·변 길이·형식 상한, SVG 문서 판별, 한글·공백 이름의 퍼센트 인코딩 경로, 도구를 모르는 하위 에이전트 그림, 저장 상태 정규화, 그래프 미리보기 블록의 위치, 휴대폰 페이로드를 확인한다. 화면(썸네일 그리기, 클릭·메뉴, 보기 창)은 GUI 실행으로만 확인할 수 있다.
