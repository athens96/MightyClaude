# 화면 공유(BETA) 기기 확인표

Mac 한 대와 안드로이드 휴대폰 한 대로 직접 해 보는 확인표입니다. 위에서 아래로 따라가면 되고, 칸마다 결과를 적습니다(`[ ]`에 체크, 빈 칸에 숫자).
기술 규약은 `docs/relay.md`("화면 공유 시그널링"), 서버 쪽은 `docs/relay-oracle.md`에 있습니다. 이 문서는 **사람이 기기로 확인할 것**만 모았습니다.

용어 한 줄 정리.
- **보기** = 휴대폰이 Mac 화면을 보기만 함. **조작** = 보면서 탭·스크롤·글자 입력까지 함.
- **경로** = 영상이 가는 길. 휴대폰 화면에 칩과 측정 줄로 표시됩니다.

| 휴대폰에 보이는 말 | 내부 이름 | 뜻 |
|---|---|---|
| 같은 와이파이 | `host` | 같은 공유기 안에서 Mac과 바로 연결 |
| P2P 직접 연결 | `srflx` (또는 `prflx`) | 밖(LTE 등)에서 NAT를 뚫고 바로 연결 |
| TURN 경유 | `relay` | 직접 연결이 막혀서 릴레이 서버(coturn)를 거쳐 돌아감 |

휴대폰 화면 말은 `srflx`와 `prflx`가 똑같이 "P2P 직접 연결"로 보입니다. 내부 이름 그대로 확인하려면 측정 결과를 내보낸 JSON의 `summary.candidateType`을 보세요(아래 3단계).

---

## 0. 준비물

- [ ] 새 Mac 빌드(설치 파일 또는 `scripts/install-macos.sh` 결과)와 새 APK.
- [ ] 휴대폰에 화면 잠금(PIN 또는 지문)이 설정되어 있음. 조작을 시작할 때마다 본인 확인을 쓰기 때문입니다.
- [ ] LTE 경로용으로 휴대폰의 Wi-Fi를 끌 수 있음. TURN 경로용으로 아래 "경로 3"의 방법 중 하나를 쓸 수 있음.
- [ ] 측정 결과를 받을 곳(내보내기는 휴대폰 공유창이 뜨므로 메모 앱·메일·메신저로 보내 두면 됩니다).

## 1. 설치와 처음 한 번만 하는 일

1. **Mac 앱 설치.** 실행 중인 앱 위에 파일을 덮어쓰지 말고 `scripts/install-macos.sh`로 설치하세요(실행 중인 앱을 바꿔치기하면 한글 입력이 깨집니다). 설치가 끝난 뒤 앱을 연다.
2. **APK 설치.** 새 APK를 휴대폰에 설치하고 앱을 연다. 기존 Mac 연결이 남아 있으면 그대로 두고, 이 Mac이 목록에 있는지만 본다.
3. **권한 다시 주기(서명 방식이 바뀐 첫 설치).** 이번 빌드부터 앱이 고정된 서명 인증서(`Mighty Claude Dev`)로 서명됩니다. 그래서 **처음 한 번은** macOS가 화면 기록과 손쉬운 사용 권한을 다시 묻습니다.
   - [ ] 시스템 설정 → 개인정보 보호 및 보안 → **화면 기록**과 **손쉬운 사용** 목록에서 Mighty Claude를 켠다. 이미 켜져 있어 보여도 **한 번 끄고 다시 켜야** 할 수 있습니다.
   - [ ] 화면 기록은 켠 뒤 앱을 완전히 종료했다가 다시 열어야 반영될 수 있습니다.
4. **권한 안내 화면.** Mac 앱 설정 → **화면 보기·조작** → **Mac 권한 확인**을 연다("화면 공유에 필요한 Mac 권한").
   - [ ] 네 줄이 모두 **허용됨**이다: 화면 기록, 손쉬운 사용, 로컬 네트워크, 알림.
   - 빠진 줄은 **허용 요청** 또는 **시스템 설정 열기**를 누르고, 끝나면 **다시 확인**.
   - 로컬 네트워크는 macOS가 상태를 알려 주지 않으면 "확인할 수 없음"으로 보일 수 있습니다. 이 빌드는 처음 같은 와이파이로 연결할 때 macOS가 "로컬 네트워크 접근" 팝업을 띄웁니다. 한 번 **허용**하세요. 팝업 문구는 "같은 Wi-Fi의 휴대폰과 화면 공유를 연결하려면 로컬 네트워크 접근이 필요합니다."입니다.
   - [ ] 팝업이 떴고 허용했다(안 떴으면 메모: ________).
5. **새로 짝지은 휴대폰은 꺼진 채로 시작하는지 먼저 확인.** 허용을 켜기 **전에**:
   - [ ] 휴대폰에서 이 Mac의 **화면 보기**를 열고 시작해 본다. "Mac 설정에서 이 휴대폰을 먼저 허용해야 합니다."로 거절된다.
   - (이미 예전에 허용한 적이 있어서 거절되지 않으면, 그 사실을 메모해 두세요: ________)
6. **휴대폰 허용과 권한.** Mac 설정 → **화면 보기·조작**의 휴대폰 목록에서
   - [ ] 이 휴대폰의 **허용**을 켠다.
   - [ ] 권한을 고른다. 먼저 **보기만**으로 시작해 "보기" 경로를 확인하고, 조작 확인 때 **조작**으로 올린다.
7. **조작 키 지문 확인(조작 권한을 줄 때).**
   - [ ] 권한을 **조작**으로 올리면 확인 창("조작 권한을 줄까요?")이 뜬다 → **조작 권한 주기**.
   - [ ] 휴대폰에서 **조작 키 등록**을 누르면, 이 Mac에 "조작 키를 등록할까요?" 창과 **지문**(`XXXX-XXXX-XXXX-XXXX`)이 뜬다.
   - [ ] 휴대폰 화면의 "이 휴대폰의 지문"과 Mac의 지문이 **글자 하나까지 같다** → **등록**. (다르면 **거절**하고 메모.)
   - [ ] 등록 뒤 Mac 설정에 "조작 키 지문 …"이 보인다.
   - [ ] **조작 시작**을 누를 때마다 휴대폰이 지문/PIN을 묻는다(열 때가 아니라 시작할 때).
8. **세션 시작 알림.**
   - [ ] 보기를 시작하면 Mac에 알림 "원격 화면 세션 시작"이 뜨고, 메뉴 막대에 원격 항목이 생긴다. 조작 중에는 "원격 조작 중" 표시가 보인다.

## 2. 세 가지 연결 경로

경로마다 **같은 순서**로 하세요: 연결 → 경로 표시 확인 → 3단계 측정. 경로가 바뀌면 휴대폰 앱의 화면 보기 창을 닫았다가 새로 시작합니다(측정 숫자는 새 연결마다 0부터 시작합니다).

경로를 확인하는 곳은 두 곳입니다.
- 화면 아래 칩 줄: **같은 와이파이 / P2P 직접 연결 / TURN 경유**
- **측정** 칩을 켜면 영상 위에 뜨는 첫 줄 `경로 … · RTT … ms · 지터 … ms`

### 경로 1. 같은 와이파이 (직접, `host`)

1. [ ] Mac과 휴대폰을 **같은 공유기의 같은 Wi-Fi**에 둔다. 손님용(게스트) Wi-Fi가 아니라 평소 쓰는 Wi-Fi여야 합니다.
2. [ ] 휴대폰 앱 → 이 Mac → **화면 보기** → **화면 보기 시작**(또는 **조작 시작**).
3. [ ] 연결되면 칩이 **같은 와이파이**다. 내부 이름은 `host`.
4. [ ] 영상 아래 품질 줄이 와이파이 상한(최대 1080p·30fps 안팎, 약 6 Mbps)을 따른다. 표시: ____
5. [ ] **원본 host 후보인지 확인.** 영상 연결이 `.local` 이름(mDNS)에 기대지 않고 진짜 IP로 맺어져야 합니다. 코드에는 후보 주소를 보여 주는 화면이 없으므로 이렇게 봅니다.
   - [ ] 연결 직전에 Mac 터미널에서 `sudo tcpdump -i en0 -n udp port 5353` 를 켜 두고(와이파이가 en0가 아니면 `route get default`로 확인) 휴대폰에서 시작한다. **무작위 문자열(UUID) 모양의 `….local` 이름을 묻거나 알리는 패킷이 없고**, 그런데도 칩이 **같은 와이파이**로 뜬다. (그런 이름이 오가면 휴대폰이 진짜 주소 대신 `.local` 가명을 쓰고 있다는 뜻입니다.)
   - [ ] 이어서 `sudo tcpdump -i en0 -n udp and host <휴대폰 IP>` 에서 Mac과 휴대폰 **사설 IP끼리** 오가는 영상 패킷이 보인다(릴레이 서버 주소가 아님).
   - 한쪽이라도 어긋나면(`.local` 질의가 보이거나, 칩이 같은 와이파이가 아니거나) 그대로 메모: ________

### 경로 2. 밖에서 LTE P2P (`srflx`)

1. [ ] 휴대폰의 **Wi-Fi를 끄고** LTE/5G만 쓴다.
2. [ ] Mac은 집/사무실 Wi-Fi에 그대로 둔다.
3. [ ] 화면 보기를 시작한다(Mac이 릴레이에 연결되어 있으므로 시작 신호는 LTE에서도 갑니다).
4. [ ] 연결되면 칩이 **P2P 직접 연결**이다. 내부 이름은 `srflx`(또는 `prflx`). 3단계의 내보낸 JSON `summary.candidateType`이 `srflx`/`prflx`이면 통과.
5. [ ] 품질 줄이 모바일 데이터 상한(최대 720p·15fps 안팎, 약 1 Mbps)을 따른다. 표시: ____
6. 칩이 **TURN 경유**로 나오면 이 통신사·공유기 조합은 직접 연결이 안 되는 것입니다. 실패가 아니라 "이 조합에서는 relay"로 기록하고, 다른 통신사/네트워크를 쓸 수 있으면 다시 해 보세요. 결과: ________

### 경로 3. 강제로 TURN 경유 (forced TURN)

**앱에는 TURN을 강제로 켜는 스위치나 개발자 메뉴가 없습니다.** 그래서 직접 연결이 일부러 안 되는 네트워크를 만들어야 합니다. 아래 중 되는 것 하나를 고르세요. 어느 쪽이든 결과는 칩 **TURN 경유**(`relay`)여야 하고, 아니면 그 방법은 TURN을 강제하지 못한 것이니 다음 방법으로 넘어갑니다.

- **방법 A. 클라이언트 격리가 켜진 Wi-Fi.** 게스트 Wi-Fi, 또는 공유기의 "AP/클라이언트 격리"를 켠 Wi-Fi에 **Mac과 휴대폰을 둘 다** 붙입니다. 같은 망이라도 기기끼리 직접 통신이 막혀 `host` 연결이 안 됩니다. (공유기가 같은 망 안의 바깥 주소 되돌림을 허용하면 `srflx`가 나올 수 있습니다.)
- **방법 B. 서로 다른 두 망 + 직접 연결이 막히는 통신사.** Mac을 다른 휴대폰/기기의 핫스팟에 붙이고 시험 휴대폰은 다른 통신사 LTE로 둡니다. 통신사 공유 주소(CGNAT)끼리는 직접 연결이 안 되는 경우가 많아 `relay`가 나옵니다.
- **방법 C. Mac 쪽 UDP 막기.** Mac에서 UDP를 막는 방화벽/VPN 규칙을 쓸 수 있으면 TURN의 TCP(3478)로만 나가게 됩니다. 규칙을 직접 만들어야 하므로 A·B가 안 될 때만 쓰세요.

확인 순서:
1. [ ] 선택한 방법: ____
2. [ ] 화면 보기를 시작한다. 연결에 몇 초 더 걸릴 수 있습니다(30초 안에 연결되지 않으면 Mac이 세션을 끝냅니다).
3. [ ] 칩이 **TURN 경유**다. 내부 이름은 `relay`.
4. [ ] TURN은 세션당 대역을 **2 Mbps**로 제한합니다. 품질 줄과 활동 비트레이트가 그보다 낮게 보이는 것이 정상입니다.
5. [ ] 이 TURN 서버는 무료 서버(`VM.Standard.E2.1.Micro`, 외부 전송 약 53 Mbps)입니다. 한 번에 한 세션만 시험하세요.

## 3. 측정 (baseline)

**경로마다 한 번씩** 아래를 똑같이 합니다. 3개 경로 × (Mac 기준 화면 1회 + 탭 100회 이상).

**기준 화면(reference scene)** 은 Mac이 주 디스플레이에 전용 창으로 재생하는 같은 장면입니다. 다른 앱은 건드리지 않습니다.

| 구간 | 시작 | 길이 | 화면 |
|---|---|---|---|
| 카운트다운 | 0초 | 3초 | 창만 뜸, 움직임 없음 |
| 움직이는 구간 | 3초 | 60초 | 문서가 초당 90pt로 올라가고, 옆 터미널에 초당 18자가 입력됨 |
| 멈춘 구간 | 63초 | 30초 | 아무 픽셀도 안 바뀜 |
| 끝 | 93초 | | |

순서:
1. [ ] 경로를 만든다(위 경로 1/2/3). 조작으로 연결한다(탭을 보내야 하므로 **조작** 권한 필요).
2. [ ] 휴대폰 화면 보기에서 **측정** 칩을 켠다. 영상 위에 `경로 … RTT …` `디코드 …` `탭→화면 p50 … p95 …` `비트레이트 움직일 때 … 멈춰 있을 때 …` 줄이 뜬다. 아래에 "Mac이 탭마다 그 지점에 표식을 그리고 답하므로…" 안내가 보이면 이 Mac이 탭 표식을 지원하는 것입니다(안 보이고 "표식을 그리지 않는 구버전" 문구가 보이면 메모).
3. [ ] Mac 설정 → 화면 보기·조작 → **측정용 장면 재생**을 누른다. 주 디스플레이에 "화면 공유 측정 장면" 창이 뜨고 3초 뒤 움직이기 시작한다.
4. [ ] 장면이 도는 동안(93초) 휴대폰을 건드리지 않고 지켜본다. 이 시간에 `비트레이트 움직일 때`와 `멈춰 있을 때` 숫자가 쌓입니다. 멈춘 구간(마지막 30초)의 비트레이트는 0에 가까워야 합니다.
5. [ ] 장면이 끝난 뒤(창에 "측정 장면이 끝났습니다") **탭을 100번 이상** 합니다. 영상 위 아무 곳이나 한 번씩 누르고, **표본 숫자가 늘어난 것을 보고 다음 탭**을 합니다(약 1~2초 간격). 너무 빨리 누르면 앞 표본이 취소될 수 있어요. `탭→화면 … (표본 N, 시간 초과 M)`에서 N이 100 이상이 될 때까지.
   - 시간 초과가 많다면(M이 N의 1/10 이상) 그 사실을 메모.
6. [ ] **측정 결과 내보내기**를 눌러 공유창으로 JSON을 받아 둔다(파일 이름에 경로를 적어 두세요: wifi / lte / turn).
   - JSON의 `summary.candidateType`이 `host` / `srflx` 또는 `prflx` / `relay` 인지 확인한다.
   - JSON의 `scene`에 `preroll`→`motion`→`still`→`done` 구간 시각이 들어 있어야 합니다.
7. 앱 화면 보기 창을 닫는다(다음 경로는 새 연결, 새 측정).

> 참고용 임시 목표(최종 합격선이 **아닙니다**): 탭→화면 p50이 와이파이 ≤200 ms / LTE ≤400 ms / TURN ≤500 ms. 비트레이트는 모바일 데이터 약 1 Mbps, 와이파이 ≤6 Mbps, 멈춘 화면은 0에 가깝게.
> **이 숫자를 넘어도 이번 확인표는 실패가 아닙니다.** 이번 측정은 기준선(baseline)을 잡는 것이고, **최종 합격 숫자는 이 결과를 보고 사용자가 정합니다.**

## 8. 문제가 생기면

- **휴대폰에 "Mac에서 승인 필요"가 뜬다.** Mac의 화면 기록 권한이 없거나 만료된 것입니다. Mac에서 시스템 설정 → 개인정보 보호 및 보안 → 화면 기록에서 Mighty Claude를 켜고(켜져 있으면 껐다 켬), 앱을 다시 연 뒤 휴대폰에서 다시 시작하세요.
- **한 달쯤 뒤 갑자기 "승인 필요"가 뜬다.** macOS가 화면 기록을 **주기적으로(대략 한 달마다) 다시 확인**합니다. Mac에 뜨는 "계속 허용" 안내나 시스템 설정에서 다시 허용하면 됩니다. 앱 문제가 아닙니다.
- **연결이 계속 "연결 중…"이다.** 30초 안에 연결되지 않으면 Mac이 세션을 끝냅니다. 먼저 Mac과 휴대폰이 둘 다 릴레이에 연결되어 있는지(휴대폰 호스트 목록에서 온라인) 확인하고, 같은 와이파이라면 Mac 권한 화면의 **로컬 네트워크**가 허용됐는지 보세요. 없으면 영상이 TURN을 거쳐 돌아가 느려집니다.
- **TURN 경유가 안 된다 / 강제 TURN을 시험할 때 연결되지 않는다.**
  - Mac에서 `bash relay/deploy/oracle/verify-live.sh`를 실행해 서버가 살아 있는지 봅니다(R1~R9가 모두 ok여야 함). R9가 깨지면 Oracle 보안 목록의 UDP/TCP 3478과 UDP 49160-49200이 닫힌 것입니다.
  - 회사·학교 망이나 방화벽이 UDP 3478을 막으면 TURN이 안 닿을 수 있습니다. 다른 망에서 시험하세요.
  - TURN 자격증명은 1시간짜리라 오래 켜 두면 갱신(ICE 재시작) 때 순간적으로 끊겼다 이어질 수 있습니다.
- **조작 키 등록이 거절된다.** Mac에 이미 다른 키가 있으면 Mac 설정에서 조작 권한을 **없음/보기만**으로 내렸다가 다시 **조작**으로 올리고(또는 **키 삭제**), 휴대폰에서 다시 등록합니다.
- **조작 중 본인 확인이 안 뜬다.** 휴대폰에 화면 잠금(PIN·지문)이 있어야 합니다. 지문이나 화면 잠금을 바꾼 뒤에는 키가 사라지므로 Mac에서 권한을 거두었다가 다시 주고 등록하세요.
- **측정 칩의 표본이 늘지 않는다.** 조작 권한이 있는지, 영상이 **연결됨** 상태인지 확인하세요. 보기 전용에서는 탭이 거절되어 표본이 안 쌓입니다.
