# 파일 창 (Mac)

워크스페이스 폴더를 읽기 전용으로 둘러보는 창이다. 왼쪽은 폴더 트리, 오른쪽은 선택한 파일의 미리보기다. 편집, 에이전트에 첨부하기는 아직 없다. 창 자체는 Mac 전용이고 Windows에는 없다. 휴대폰은 같은 규칙으로 Mac의 워크스페이스를 읽는다(아래 "휴대폰").

## 여는 방법

- 워크스페이스 제목줄 오른쪽의 폴더 버튼
- 메뉴 **워크스페이스 → 파일 창 열기** (⇧⌘E)

워크스페이스마다 파일 창은 하나다. 이미 열려 있으면 다시 열 때 그 창으로 이동한다. 처음 열면 현재 실행 창의 왼쪽으로 분할하고, 분할할 자리가 없으면 같은 그룹의 탭으로 들어간다. 다른 실행 창처럼 탭을 끌어 옮기고, 분할하고, 닫는다([pane-layout.md](pane-layout.md)).

파일 창은 에이전트의 터미널 창처럼 저장하지 않는다. 앱을 다시 켜면 사라지고 필요할 때 다시 연다. 펼친 폴더와 선택한 파일은 워크스페이스별로 앱이 켜져 있는 동안 기억하므로, 창을 닫았다 다시 열면 그대로다. 창을 닫으면 미리보기 내용(큰 텍스트·이미지)은 메모리에서 내려놓고, 다시 열 때 선택한 파일을 새로 읽는다.

파일 창은 에이전트가 아니다. 에이전트 동반자(상태 목록·알림)와 상태 막대 사용량, 모델 목록 갱신은 파일 창을 세지 않는다.

## 트리

- 폴더를 누를 때 그 폴더만 읽는다(지연 로딩). 폴더 먼저, 그다음 파일이며 각각 Finder와 같은 대소문자 무시·자연 정렬(`file2` 다음 `file10`)이다.
- 숨김 파일(`.env`, `.gitignore` 등)도 보인다.
- `.git`, `node_modules`, `.build`, `build`, `dist`, `DerivedData`, `.next`, `Pods`, `.venv`, `__pycache__` 폴더는 흐리게 표시하고 절대 자동으로 펼치지 않는다. 직접 누르면 열린다.
- 한 폴더에서 최대 5,000개 항목만 보여 주고 나머지가 있으면 알린다. 디스크에서는 이름을 20,000개(`WorkspaceFiles.maximumEnumeratedNames`)까지만 읽어 그중에서 고르므로, 수십만 개짜리 폴더도 전부 확인·정렬하지 않는다(그런 폴더의 처음 5,000개는 전체 정렬 순서의 처음과 다를 수 있다).
- 폴더를 펼칠 때마다 그 폴더를 다시 읽는다(이전에 읽은 목록은 읽는 동안만 보인다).
- 새로 고침 버튼은 루트와 펼친 폴더, 선택한 파일을 다시 읽고, 접힌 폴더의 예전 목록은 버린다.
- 키보드: 위·아래로 이동, 오른쪽은 펼치기(펼친 폴더에서는 첫 항목으로), 왼쪽은 접기(접힌 항목에서는 상위 폴더로), Return은 폴더 펼치기/접기.
- 이름 필터는 루트와 펼친 폴더의 목록에서만 이름을 찾는다. 디스크를 새로 뒤지지 않는다. 앞뒤 공백·줄바꿈은 무시한다. 결과는 최대 2,000개이며 더 있으면 "처음 2,000개만 표시" 안내가 나온다.
- 필터 중에는 폴더를 펼친 모양으로 보여 주지 않는다. 필터 결과의 폴더에서 Return이나 오른쪽 키를 누르면 필터를 지우고 그 폴더(와 상위 폴더)를 펼쳐 트리에서 보여 준다. 왼쪽 키는 필터 중에는 아무것도 하지 않는다. 폴더를 누르면 선택만 된다.

## 보안 규칙

루트는 워크스페이스 폴더다. 모든 경로는 심볼릭 링크를 풀어 실제 경로를 구하고, 그 실제 경로가 루트이거나 루트 안일 때만 목록에 올리거나 읽는다.

- 루트 밖을 가리키는 심볼릭 링크(파일이든 폴더든)와 끊어진 링크는 트리에 나타나지 않는다. 루트 안을 가리키는 링크는 작은 화살표와 함께 보인다.
- `..`나 절대 경로로 루트를 벗어날 수 없다.
- 미리보기는 경로를 해석한 뒤 `open(O_RDONLY|O_NOFOLLOW|O_NONBLOCK)`으로 연다. 마지막 경로 요소가 그사이 심볼릭 링크로 바뀌었으면 열지 않는다. `fstat`로 일반 파일인지 확인하고, 열린 파일의 실제 경로(`fcntl(F_GETPATH)`)가 루트 안인지 다시 확인한 다음, 그 파일 디스크립터로만 읽는다.
- FIFO·소켓·장치 파일은 열어도 멈추지 않고 읽지도 않으며 "미리볼 수 없는 파일" 카드로 보인다.
- 권한이 없는 폴더·파일은 앱을 멈추지 않고 "읽을 수 없습니다"로 표시한다.
- 아무것도 쓰지 않으며, 원격 내용을 불러오지 않는다.

구현은 `MightyCore/WorkspaceFiles.swift`(`WorkspaceFiles`, `TextEncoding`, `FilePreviewClassifier`)와 `MightyCore/SourceHighlighter.swift`(`SourceLines`, `SourceHighlighter`)이며 `WorkspaceFilesTests`가 정렬·잡음 폴더·링크 탈출·안전한 열기(FIFO, 마지막 요소 링크, 루트 밖 실제 경로)·분류·인코딩·크기 제한·줄 나누기·강조 토큰을 검사한다.

### 읽기

파일을 고르면 약 100 ms 기다렸다가 메인 스레드 밖에서 읽는다. 화살표로 빠르게 지나가면 지나간 파일은 읽지 않는다. 새 파일을 고르면 이전 읽기는 머리 읽기·전체 읽기·디코딩·강조 사이에서 멈추고, 늦게 끝난 이전 결과는 요청 번호가 달라 버린다. 파일 정보 조회, 강조, 줄 번호 표, 색칠한 텍스트, Markdown 파싱, 이미지 디코딩도 모두 메인 스레드 밖에서 한다.

### 인코딩

1. BOM이 있으면 그 인코딩: UTF-8, UTF-16 LE/BE, UTF-32 LE/BE. UTF-16/32 BOM이 있으면 NUL 바이트가 있어도 텍스트로 본다.
2. BOM이 없고 NUL 바이트가 있으면 바이너리.
3. UTF-8로 깨끗이 풀리면 UTF-8.
4. 아니면 CP949(EUC-KR을 포함하는 Windows 한국어)로 깨끗이 풀리면 CP949.
5. 모두 아니면 바이너리.

표시하는 텍스트도 같은 순서로 찾은 인코딩으로 풀고, 머리줄에 이름(`UTF-8`, `UTF-16 LE`, `CP949 (EUC-KR)` 등)을 보인다. 1 MB에서 자른 끝이 글자 중간이면 그 조각만 뺀다.

### 줄 번호

NSTextView와 같은 곳에서 줄을 나눈다: `\n`, `\r`, `\r\n`(한 줄바꿈), U+2028, U+2029. 줄을 접으면 이어지는 줄에는 번호가 없다.

### 이미지

- 비트맵은 ImageIO로 메인 스레드 밖에서 푼다. 픽셀 크기는 파일 속성에서 읽고(회전 정보 반영), 창에 맞추기는 긴 변 4,096픽셀 이하 축소본으로 그린다.
- 실제 크기(1:1)와 확대는 처음 그렇게 볼 때에만 원본 크기로 푼다. 1억 픽셀(100 MP)이 넘으면 원본 크기로 풀지 않고 "창에 맞춘 크기로만" 안내와 함께 확대 버튼을 끈다.
- 실제 크기는 이미지 1픽셀이 화면 1픽셀이다. Retina(배율 2)에서는 픽셀 크기를 배율로 나눈 포인트로 그린다. 창에 맞추기도 이 크기보다 키우지 않는다. svg·pdf는 문서의 포인트 크기를 그대로 쓴다.
- 확대는 이미지의 긴 변이 16,384포인트를 넘지 않는 데서 멈춘다(svg·pdf 포함).

알려진 한계:

- Markdown 안의 이미지는 불러오지 않고 대체 텍스트만 보인다(대화창 렌더러와 같은 규칙). 로컬 링크는 눌러도 열리지 않고, http(s) 링크만 기본 브라우저로 열린다.
- UTF-8·UTF-16·UTF-32·CP949가 아닌 인코딩(Shift_JIS, Latin-1 등)은 바이너리로 보거나 CP949로 잘못 읽을 수 있다.
- 강조는 한 줄 스캐너라 언어별 문법을 완전히 따르지 않는다.

## 휴대폰

파일 창(`kind: "files"`, id `files:<워크스페이스 id>`)은 릴레이 창 목록에 싣지 않는다. 휴대폰이 그 id로 명령을 보내도 "찾을 수 없음"으로 답한다([mobile-remote.md](mobile-remote.md)).

대신 휴대폰 앱에는 따로 읽기 전용 파일 화면이 있다. 호스트 화면에서 워크스페이스 이름 옆 **파일**을 누른다(Mac이 `files` capability를 알릴 때만 보인다). 요청은 종단 간 암호화된 릴레이의 `GET /m1/workspaces/{id}/files`·`…/file` 두 라우트로 가고, Mac은 이 창과 **같은 함수**로 목록을 만들고 파일을 연다. 위 보안 규칙이 그대로 적용되며, 휴대폰의 경로는 그 앞에서 한 번 더 걸러진다(절대 경로·`..` 거절). 라우트·한도·오류 코드는 [mobile-remote.md](mobile-remote.md)의 "파일" 절.

- **폴더**: 한 번에 한 폴더. 위쪽 경로 줄(누르면 그 폴더로), 맨 위 `상위 폴더` 줄. 뒤로 가기는 두 플랫폼 모두 루트에 닿을 때까지 상위 폴더로 먼저 간다: 머리줄의 뒤로 단추, iOS 왼쪽 가장자리 밀기, Android 뒤로 버튼(`usePreventRemove`로 이 화면이 닫히는 뒤로 동작만 가로챈다. 다른 이동은 그대로). 폴더 먼저·자연 정렬(Mac 순서 그대로), 잡음 폴더는 흐리게, 링크는 `↗`, 파일은 크기와 수정일. 당겨서 새로 고침. 이름 필터는 **현재 폴더**의 목록에서만 찾는다(대소문자·한글 자모 조합 무시). 한 폴더에서 2,000개까지만 받고 넘으면 실제로 받은 개수와 함께 알린다(Mac 창은 5,000개. Mac은 한 폴더에서 이름을 20,000개까지만 읽는다).
- **소스·텍스트**: 고정폭 글꼴, 줄 번호, 한 줄씩 그려 큰 파일도 스크롤이 가볍다. 가로 스크롤, 5,000자보다 긴 줄이 있으면 Mac처럼 줄을 접는다. 강조는 Mac `SourceHighlighter`를 그대로 옮긴 `mobile/src/lib/highlight.ts`(같은 처음 400,000 UTF-16 단위 제한)이고, 두 구현을 `native/contracts/fixtures/source-highlight.json` 하나로 검사한다. 머리줄에 크기·인코딩·줄 수. 파일 앞 512 KiB만 받으며(Mac 창은 1 MB) 잘렸으면 알린다.
- **Markdown**: 대화창과 같은 렌더러(`AssistantMarkdown`)로 그리고 `원본`으로 바꿀 수 있다. Markdown 안의 이미지는 Mac처럼 불러오지 않고 대체 텍스트만 보인다(대화창도 같다: 렌더러 기본 규칙은 http(s) 주소를 불러오고 다른 경로에는 `https://`를 붙여 불렀다). 131,072바이트가 넘으면 렌더링하지 않고 원본을 보여 준다. 파일이 잘렸으면 어느 경우든(렌더링했든, 원본이든, 너무 커서 원본만 보이든) 잘렸다고 알린다.
- **이미지**: Mac이 만든 썸네일(긴 변 2,048픽셀 이하, 512 KiB 이하 JPEG/PNG)을 화면에 맞춰(썸네일 크기보다 키우지 않음) 보여 주고, 두 손가락으로 벌려 최대 8배, 두 번 탭하면 2.5배/원래대로. 원본 픽셀 크기를 표시한다. svg는 Mac 앱이 AppKit으로 그린 그림, pdf는 첫 쪽이다. 바깥 파일·주소를 부를 수 있는 svg, 크기가 말이 안 되는(무한대, 한 변 10,000,000포인트 초과) svg·pdf는 Mac이 그리지 않고, 1억 픽셀이 넘는 비트맵은 풀지 않는다([mobile-remote.md](mobile-remote.md) "파일"의 svg 규칙). 이미지는 Mac에서 한 번에 하나씩만 풀고, 파일을 빨리 넘기면 기다리던 이전 이미지는 풀지 않는다.
- **그 밖**: "미리볼 수 없는 파일" 카드에 이름·크기·수정일과 이유(바이너리, 일반 파일 아님, 50 MB·1억 픽셀 초과 이미지, 그리지 않은 이미지).
- 경로가 너무 길면(요청 경로가 16 KiB를 넘으면) Mac이 버리지 않고 바로 답하므로, 제한 시간까지 기다리지 않고 "경로가 너무 길다"는 오류를 보인다.
- 불러오는 동안은 진행 표시, 실패하면 오류 줄과 **다시 시도** 버튼. 연결이 끊겨 실패했으면 다시 연결되는 순간 저절로 다시 읽는다. 밝은·어두운 테마를 따르고, 목록 줄·경로 줄·이미지에 접근성 이름이 있다.
