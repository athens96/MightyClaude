# Windows CLI environment and terminal profiles

The Windows host refreshes CLI credentials before a run, account changes and a forced model-catalog refresh. `CliEnvironment` starts from the app's environment and freshly reads persisted Windows Machine/User provider variables and PATH. `WindowsShellEnvironment` then captures the environment of the same PowerShell executable used by the app terminal (`PseudoTerminal.DefaultShell`). This closes the case where `AWS_BEARER_TOKEN_BEDROCK` exists only in a terminal profile while the GUI was launched from Explorer.

The current shell is system Windows PowerShell 5.1, with its normal ConsoleHost profiles. PowerShell 7 and VS Code can have different profiles; values stored only in those host-specific profiles are not imported. Microsoft documents both [process inheritance and profile environment variables](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_environment_variables) and [profile order, host-specific paths and execution-policy restrictions](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_profiles). Claude's own user/project/managed settings still have their normal CLI precedence; importing a profile does not override those settings or verify Bedrock model access.

Capture runs in the user's home directory, never in the workspace. Normal profile execution policy remains in force: there is no execution-policy bypass or project-file sourcing. The process runs noninteractively with a four-second capture deadline and Windows job ownership so prompts, hangs and child processes are terminated during cleanup. An absent PowerShell, blocked/broken profile, malformed output or deadline falls back to the process/registry environment. No profile, registry or credential file is modified.

Only a complete, nonce-framed, bounded environment snapshot is accepted. Standard output and error remain in memory and are never logged, persisted in the app state or included in diagnostics. The ten-second cache is refreshed forcibly before actual runs and account/model refreshes. A forced refresh waits for an older capture and then performs a new one; it cannot join an already-started capture. If that new capture fails, the old captured token is discarded. Values removed by a successful fresh profile capture remain explicitly unset in child processes.

`CliEnvironmentVerification` checks framing, case-insensitive duplicate rejection, output limits, redacted diagnostics, token rotation, explicit deletion, cancellation, timeout fallback and forced refresh ordering. The Windows-only `WindowsCaptureWire` test executes the real PowerShell serializer with synthetic values and `-NoProfile`; it never reads the user's personal profile. Real PowerShell-profile credentials and Bedrock inference still require a device/account check. The app terminal remains responsible for any interactive sign-in or profile prompt.
