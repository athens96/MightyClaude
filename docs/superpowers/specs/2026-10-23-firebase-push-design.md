# Firebase 연동: 폰 푸시 알림 · Crashlytics · App Distribution

2026-10-23 · 사용자와 정한 설계 (brainstorming)

## 목표
연결된 맥(또는 윈도우) 호스트에서 작업이 끝나거나, 멈춰서 사람이 골라야 할 때 폰에 알림이 오고, 폰에서 그 알림을 처리할 수 있다. 폰 앱의 충돌을 Crashlytics로 모으고, 릴리즈 APK를 Firebase App Distribution으로도 테스터에게 보낸다.

## 사용자가 정한 것
1. Firebase 프로젝트는 사용자에게 이미 있다. 거기에 안드로이드 앱(`dev.mightyclaude.mobile`)을 등록해 쓴다.
2. 푸시는 **릴레이 서버**가 보낸다. FCM을 보내는 서비스 계정 키는 릴레이 서버에만 둔다(저장소·앱 배포본에 넣지 않는다).
3. 알림 내용은 **호스트가 폰 키로 암호화**하고 폰이 풀어서 보여 준다. 릴레이와 Google은 내용을 읽지 못한다(FCM 데이터 메시지).
4. 권한 요청 알림에는 **버튼**을 붙여 알림에서 바로 답한다(Claude: 허용·거절, Antigravity: 이번만 허용·항상 허용·거절). 선택 질문·계획 승인 등은 누르면 그 세션을 연다.
5. 알림을 보내는 일: **작업 완료, 작업 실패, 권한 요청, 질문, 계획 승인, 로그인 만료** 모두.
6. App Distribution은 **함께 쓰기**: 릴리즈 때 같은 APK를 테스터에게도 올리고, R2 다운로드 페이지는 그대로 둔다. 테스터 주소는 릴리즈 도구의 로컬 설정에만 둔다(공개 저장소에 넣지 않는다).

## 범위
- 폰: 안드로이드만(지금 iOS 빌드가 없다). Crashlytics는 폰 앱만.
- 호스트: 맥이 기준이고 윈도우 호스트도 같게 보낸다.
- 릴레이: 토큰 등록과 푸시 전달 두 가지를 더한다.

## 구조
```
호스트(맥·윈도우) ──인증된 HTTPS──▶ 릴레이 ──FCM 데이터 메시지──▶ 폰
  이벤트를 폰 키로 암호화           핸들→토큰 조회, 서비스 계정 키      복호화 → 알림/버튼
```

### 푸시 핸들
- 폰은 FCM 토큰을 받으면 릴레이에 등록하고 **푸시 핸들**(무작위 128비트 이상, 추측 불가)을 받는다. 토큰이 바뀌면 같은 핸들로 갱신한다.
- 폰은 핸들을 페어링된 호스트에게만 암호화 채널(m1)로 알려 준다. 호스트는 핸들만 알고 토큰은 모른다.
- 호스트는 자기 인증(기존 호스트 토큰 증명, serverId)으로 `핸들 + 암호문`을 릴레이에 보낸다. 릴레이는 핸들을 처음 쓴 serverId에 묶어, 다른 serverId가 같은 핸들로 보내지 못하게 한다(폰이 다른 호스트와도 페어링하면 호스트마다 핸들을 따로 받는다).
- 폰이 페어링을 지우면 그 핸들을 릴레이에서 지운다. FCM이 토큰을 무효라고 답하면 릴레이가 핸들을 지운다.

### 암호화
- 기존 페어링의 비밀에서 푸시 전용 키를 파생(HKDF, 라벨 `mighty-push-v1`)하고 AEAD로 봉인한다. 호스트와 폰 밖에서는 열 수 없다. 정확한 키 출처는 계획 단계에서 지금 페어링 코드에 맞춰 정한다(릴레이 연결과 Tailscale 직접 연결 모두 같은 키를 쓸 수 있어야 한다).
- 평문 내용: 종류(완료·실패·권한·질문·계획·로그인), 호스트 이름, 워크스페이스, 창 제목, 한 줄 요약, 세션 id, 권한 요청 id와 runId(권한일 때), 버튼 종류, 만든 시각. 길이 제한(FCM 4KB 안).

### 호스트의 이벤트
- 이벤트 6종이 생기면 그 호스트에 핸들을 준 폰마다 하나씩 보낸다. 같은 이벤트는 한 번만 보낸다(이벤트 id로 중복 제거).
- 폰이 그 세션을 **지금 보고 있으면** 보내지 않는다. 폰 앱은 화면에 띄운 세션을 호스트에 알려 준다(앞쪽에 있을 때만, 짧은 유효 시간).
- 릴레이에 닿지 못하면 짧게 몇 번 다시 보내고 버린다(알림은 최선 노력이다. 폰을 열면 상태는 늘 호스트에서 다시 읽는다).
- Tailscale 직접 연결로 붙은 폰도 알림은 릴레이로 간다(호스트가 인터넷에 닿으면 된다).

### 폰의 처리
- 백그라운드 메시지 처리기가 복호화해 로컬 알림을 띄운다. 복호화할 수 없는 메시지는 버린다.
- 권한 알림의 버튼은 **잠금을 푼 뒤에만** 동작한다. 버튼을 누르면 앱이 백그라운드에서 호스트에 기존 응답(`POST /m1/sessions/{id}/permission`, Antigravity는 `always` 포함)을 보낸다. 실패하거나 시간이 넘으면 앱을 그 세션의 카드로 연다. 성공하면 알림을 "허용함/거절함"으로 바꾼다.
- 알림을 누르면 그 호스트·세션 화면이 열린다.
- 이미 처리된 요청(맥에서 먼저 답함 등)에 버튼을 누르면 호스트의 409를 받아 "이미 처리됨"으로 바꾼다.
- 설정에 알림 켜기/끄기(이벤트 종류별)를 둔다. 기본은 모두 켬. 안드로이드 13 이상은 알림 권한을 처음 한 번 묻는다.

### Crashlytics
- 폰 앱의 네이티브 충돌과 처리되지 않은 JS 오류를 보낸다. 사용자 내용(대화·명령·경로)은 기록에 넣지 않는다. 설정에서 끌 수 있다(기본 켬).

### App Distribution
- 릴리즈 도구(`~/Work/.mc-release`)에 단계 하나를 더한다: APK를 만든 뒤 Firebase CLI로 테스터에게 올리고 릴리즈 노트를 붙인다. 테스터 주소는 그 로컬 설정에만 둔다.

## 보안
- 서비스 계정 키·FCM 토큰은 릴레이에만 있다. `google-services.json`은 공개 저장소에 넣지 않고 빌드 때 로컬 파일에서 넣는다.
- 릴레이는 핸들을 아는 호스트(첫 사용 serverId)만 보낼 수 있고, serverId별·IP별·전체 전송 한도를 둔다(지금 TURN 한도와 같은 방식).
- 알림 버튼의 허용은 잠금 해제를 요구하고, 실제 판단은 늘 호스트가 한다(지금 폰 답변 경로와 같은 검사·Antigravity 규칙 안전 검사).
- 내용은 종단 간 암호화되어 릴레이 로그·Google에 남지 않는다.

## 실패 처리
- 릴레이가 꺼져 있거나 FCM이 실패해도 앱 동작은 그대로다(알림만 안 온다). 호스트는 실패를 진단 기록에만 남긴다.
- 폰이 꺼져 있거나 절전이면 FCM이 늦게 줄 수 있다. 버튼 응답이 늦어 요청이 사라졌으면 "이미 처리됨"으로 보인다.

## 사용자가 해 줄 설정 (구현 중 안내)
1. Firebase 콘솔에서 안드로이드 앱 `dev.mightyclaude.mobile` 등록 → `google-services.json` 받기(로컬에만 둔다).
2. FCM 전송 권한이 있는 서비스 계정 키를 만들어 릴레이 서버의 `.env` 옆 파일로 둔다(서버 재배포).
3. App Distribution을 켜고 Firebase CLI에 로그인(`firebase login`, 터미널 창에서 직접).

## 테스트
- 핸들 등록·전송·권한 검사·한도(릴레이 단위 테스트, FCM은 가짜 전송기).
- 암호화 왕복과 변조 거절(맥·윈도우·폰이 같은 공유 픽스처를 읽는다).
- 호스트 이벤트 6종 → 전송 내용, 중복 제거, "보고 있으면 안 보냄"(맥·윈도우).
- 폰: 복호화 → 알림 모양, 버튼 → 응답 요청, 실패 → 앱 열기, 409 → 이미 처리됨(jest).
- 실제 기기에서의 도착·버튼·잠금 해제는 사용자 확인 항목.

## 범위 밖
iOS 푸시, 맥·윈도우 앱의 Crashlytics, 알림으로 질문에 답하기(선택지 버튼).
