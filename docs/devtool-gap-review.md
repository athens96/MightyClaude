# 개발 도구 관점의 빈자리 검토 (2026-11-09)

Mighty Code를 "AI CLI를 감싼 개발 도구"로 보고, 지금까지 구현된 것(문서 `docs/`, 도움말 원문 `docs/help/content/ko/`, Mac 소스 `native/macos/Sources/`)을 기준으로 개발자의 하루 흐름에서 비어 있는 자리를 관점별로 정리했다. 이 검토 뒤에 1–10번을 Mac 앱에 구현했다. 구현 기록은 [`docs/devtool-features.md`](devtool-features.md)에 있다. 각 항목은 **지금 있는 것 → 비어 있는 것 → 제안**의 순서이고, 이미 있는 부품을 다시 쓸 수 있는 것을 우선했다.

실행·관찰·승인 쪽은 촘촘하다. 비어 있는 곳은 대체로 **에이전트가 만든 결과를 개발자가 검토하고 내보내는 쪽**(리뷰·되돌리기·커밋·PR)과 **지난 작업을 다시 찾고 재사용하는 쪽**(검색·프롬프트·비용 집계)이다.

## 1. 결과 검토와 되돌리기 — 우선순위 높음

**있는 것.** `FileOriginalStore`(`AppStore.swift:326`)가 요청이 파일을 처음 바꾸기 전 내용을 저장하고, 블록의 참조 말풍선(`MightyGraphReferenceBubble.swift:214`)과 파일 창이 그 기준으로 diff를 보여 준다. 오케스트레이션 자식은 병합 되돌리기가 있다.

**비어 있는 것.**
- 일반 창(자식이 아닌 창)의 요청이 만든 변경을 **되돌리는 동작이 없다.** 원본은 이미 저장되어 있는데 보기에만 쓴다.
- 변경 검토가 파일 하나씩이다. "이번 요청이 바꾼 파일 전체"를 한 화면에서 넘겨 보는 리뷰 화면이 없다.
- diff의 줄에 의견을 달아 에이전트에게 돌려보내는 길이 없다(지금은 손으로 경로·줄을 적어 다시 요청해야 한다).

**제안.**
1. **요청 되돌리기**: 결과 블록/결과 파일 목록에 "이 요청의 변경 되돌리기"(파일별·전체). `FileOriginal`을 다시 쓰되, 그 뒤에 사람이나 다른 요청이 같은 파일을 고쳤으면 거부(현재 내용 해시 비교) — 병합 되돌리기의 "바뀐 것은 없습니다" 규칙과 같은 원칙.
2. **변경 리뷰 화면**: 결과 파일 목록 + 파일별 diff를 한 창에서 ↑↓로 넘기기. 파일 창의 diff 뷰(`FileDiffView.swift`)를 그대로 쓴다.
3. **줄 의견 → 후속 요청**: diff 줄을 골라 의견을 달면 `path:line` + 의견이 입력창에 쌓이고, 한 번에 보낸다. 휴대폰에서도 같은 구조로 쓸 수 있다.

## 2. 커밋·브랜치·PR — 우선순위 높음

**있는 것.** git 배지(브랜치·변경 개수), 워크스페이스 만들기의 git 처리(`WorkspaceCreateGit.swift`), worktree 관리. 작업 지도는 태그·CI·릴리스 단계를 읽는다.

**비어 있는 것.** 앱 안에서 스테이징·커밋·브랜치 전환·PR 생성을 하지 않는다. 지금은 에이전트에게 "커밋해 줘"라고 하거나 터미널로 간다. `gh`/`glab` 연동은 없다(`gh pr` 언급 0곳).

**제안.**
1. **커밋 시트**: git 배지를 누르면 변경 파일 목록(체크로 고르기) + 커밋 메시지 칸 + "에이전트에게 메시지 쓰게 하기". 메시지 생성은 지금 창의 CLI에 짧은 요청으로 보내면 되므로 새 모델 호출 경로가 필요 없다.
2. **PR 만들기/보기**: `gh pr create`·`glab mr create`를 에이전트 터미널로 실행(로그인 프롬프트 규칙 그대로). 열린 PR의 CI 상태와 리뷰 의견 개수를 배지 옆에 표시.
3. **CI 실패 → 요청**: CI가 실패하면 실패 로그 꼬리를 붙인 "고쳐 줘" 초안을 입력창에 넣는 다음 행동 버튼(`NextActions.swift`에 한 종류 추가).

## 3. 여러 에이전트 비교 — 우선순위 중간, 차별점 큼

**있는 것.** 오케스트레이션 자식이 Claude·Codex·Antigravity 중 아무 것으로나 뜨고, 각자 worktree에서 일하며 보고서를 남긴다.

**비어 있는 것.** "같은 요청을 셋에게 동시에 시키고 결과를 나란히 비교해 하나를 고르는" 흐름이 없다. 세 CLI를 한 창에 모은 앱이라는 점을 가장 잘 살릴 수 있는 기능인데 비어 있다.

**제안.** 입력창의 "비교 실행": 고른 에이전트 수만큼 자식을 같은 요청으로 띄우고, 끝나면 비교 카드(바뀐 파일 수·+/−·소요 시간·비용·테스트 결과)를 보여 준다. 고른 것만 병합하고 나머지는 폐기. 병합·폐기는 기존 카드 동작을 그대로 쓴다.

## 4. 지난 작업 찾기 — 우선순위 중간

**있는 것.** `SessionHistory.swift`가 세 CLI의 세션 파일(Claude `projects/*.jsonl`, Codex `rollout-*.jsonl`, Antigravity `transcript_full.jsonl`)을 이미 읽는다. 세션 이어가기 목록은 이 폴더의 세션을 시간순으로 보여 준다. ⌘K는 워크스페이스 검색이다.

**비어 있는 것.** 대화 **내용**으로 찾는 검색이 없다("그때 그 마이그레이션 어떻게 했지?").

**제안.** ⌘K에 "대화 검색" 탭: 세션 파일을 앱이 색인(요청 텍스트와 최종 답만, 로컬 SQLite FTS)하고, 결과를 누르면 그 세션을 이어가기로 연다. 세션 하나를 Markdown으로 내보내기(공유·이슈 첨부용)도 같은 파서로 된다.

## 5. 프롬프트·작업 재사용 — 우선순위 중간

**있는 것.** 새 창이 직전 창의 모델·사고 강도·권한을 물려받는다(`SessionTemplate.swift`). 스타일은 "어떻게 진행할지"를 정한다. 슬래시 명령은 CLI의 스킬을 부른다.

**비어 있는 것.** 자주 쓰는 요청 문장("이 PR 리뷰해 줘, 보안 위주로", "릴리스 노트 써 줘")을 저장해 두는 곳이 없다. 스킬을 만들기엔 가볍고, 매번 치기엔 길다.

**제안.** 워크스페이스별·전역 **저장한 요청**: `/` 목록에 같이 뜨고 `{선택한 파일}`·`{브랜치}` 같은 자리표시자를 채운다. 휴대폰에서 한 번 눌러 보내기에 특히 쓸모 있다(휴대폰에서 긴 요청을 치기 어렵다).

## 6. 비용과 사용량 집계 — 우선순위 중간

**있는 것.** 세션별 토큰·`costUSD`(컨텍스트 고리, `SessionInfoViews.swift`), 계정 한도와 리셋권(`AccountUsageService.swift`).

**비어 있는 것.** 기간·워크스페이스·모델·스타일별 **누적** 집계와 예산 알림이 없다. 페이즈별 모델 라우팅이 실제로 비용을 줄였는지 확인할 방법이 없다.

**제안.** 설정 또는 작업 현황에 "사용량" 화면: 일/주별 막대, 워크스페이스·모델별 표. 하루 예산을 넘으면 상태 줄 경고와 휴대폰 푸시. 데이터는 이미 런마다 받는 값을 런 기록에 남기기만 하면 된다.

## 7. 프로젝트 맥락 관리 — 우선순위 중간

**있는 것.** 플러그인·마켓플레이스 관리, 도구 모음 탐지, statusLine. 앱이 띄우는 MCP 서버(에이전트 터미널, 오케스트레이션)는 자동 연결된다.

**비어 있는 것.**
- `CLAUDE.md`·`AGENTS.md`·`GEMINI.md`를 보고 고치는 곳이 없다(소스에서 `CLAUDE.md` 언급 0곳). 세 CLI가 서로 다른 파일을 읽어서 내용이 어긋나기 쉽다.
- 사용자가 직접 넣은 MCP 서버를 CLI별로 보고 켜고 끄는 화면이 없다.
- Claude hooks가 설정돼 있는지 보이지 않는다(앱 자신의 `mods/mighty-bridge` 말고).

**제안.** 워크스페이스 설정에 "에이전트 맥락" 탭: 세 지침 파일을 나란히 보여 주고 차이를 표시, "하나를 기준으로 맞추기". 같은 탭에 CLI별 MCP 서버·hooks 목록(읽기 + 켜기/끄기).

## 8. 실행·확인 루프 — 우선순위 낮음~중간

**있는 것.** 실제 터미널, 에이전트 터미널(개발 서버 등), 브라우저 창, 웹 열기 선택.

**비어 있는 것.** 프로젝트의 실행 명령(`package.json` scripts, `Makefile`, `swift test` 등)을 알아보고 버튼으로 돌리는 곳이 없고, 떠 있는 개발 서버 포트를 모아 보는 곳이 없다.

**제안.** 제목줄의 "작업" 메뉴: 탐지한 스크립트를 터미널 창에서 실행, 실패하면 출력 꼬리를 붙여 에이전트에게 보내기. 열려 있는 포트 목록 → 누르면 브라우저 창으로.

## 9. OS·외부 연결 — 우선순위 낮음

**비어 있는 것.** URL 스킴, 셸 명령, macOS 단축어(App Intents), 서비스 메뉴가 없다(`mightyclaude://`·`AppIntent` 0곳). 푸시는 휴대폰만 받고 Slack·Discord 웹훅은 없다.

**제안.**
- `mighty .` 셸 명령(설치는 설정 → 구성 요소): 지금 폴더를 워크스페이스로 열기, `mighty "요청"`으로 바로 보내기.
- `mightyclaude://open?path=…&prompt=…` — 이슈 트래커·문서에서 링크 한 번으로 요청 시작.
- 단축어 동작 "Mighty Code에 요청 보내기", Finder 빠른 동작 "이 폴더에서 Claude 열기".
- 완료·실패 알림을 웹훅으로도 보내기(내용은 제목만, 휴대폰 푸시와 같은 범위).

## 10. 신뢰와 진단 — 우선순위 낮음

**있는 것.** 진단 코드가 많다(`*Diagnostics.swift` 20여 개), 스모크 테스트 모드, 승인 카드, 스타일 신뢰 저장소.

**비어 있는 것.**
- 사용자가 버그를 보고할 때 쓸 **진단 묶음 내보내기** 단추가 없다(로그·버전·CLI 버전·설정 요약을 비밀값 빼고 zip으로).
- 요청 하나가 실행한 명령·바꾼 파일·연 URL을 한 줄씩 보는 **감사 기록**이 블록 다이어그램 안에 흩어져 있다. 자동 편집 모드로 오래 돌린 뒤 "무엇을 했나"를 확인하기 어렵다.
- 커밋 전 비밀값 검사(키·토큰 패턴)가 없다. 2번의 커밋 시트에 붙이면 자연스럽다.

## 추천 순서

| 순서 | 항목 | 이유 | 대략 크기 |
|---|---|---|---|
| 1 | 요청 되돌리기 (1-1) | 원본이 이미 저장돼 있어 동작만 붙이면 됨. 자동 편집 모드의 불안을 바로 줄임 | 작음 |
| 2 | 변경 리뷰 화면 + 줄 의견 (1-2, 1-3) | 에이전트 결과 검토가 개발 도구의 핵심 루프 | 중간 |
| 3 | 커밋 시트 + PR (2) | 터미널로 나가는 가장 잦은 이유 | 중간 |
| 4 | 비교 실행 (3) | 세 CLI를 모은 앱만 할 수 있는 기능, 오케스트레이션 재사용 | 중간 |
| 5 | 대화 검색 (4) | 파서가 이미 있음 | 중간 |
| 6 | 저장한 요청 (5) | 휴대폰 사용성까지 같이 올라감 | 작음 |
| 7 | 사용량 집계 (6), 에이전트 맥락 (7) | 운영 편의 | 중간 |
| 8 | 나머지 (8–10) | 있으면 좋음 | 작음~중간 |

모든 항목은 Mac·Windows가 같은 계약(`native/contracts/`)을 따르는 지금 구조에 맞춰, 모델 규칙을 Core에 두고 화면만 플랫폼별로 만드는 방식을 전제로 했다. 원격 워크스페이스에서는 1·2·4가 호스트 쪽 실행이 필요하므로 원격 프로토콜에 요청 종류를 더해야 한다.
