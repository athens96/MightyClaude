# 마이티 모드 (Claude · Codex)

Claude 또는 Codex 실행 창 상단에서 **기본 / 마이티**를 선택한다. 기본은 기존 대화 화면이며, 마이티는 같은 실행과 대화를 요청별 그래프로 표시한다. 전환해도 대화를 새로 시작하거나 입력 중인 내용을 지우지 않는다. 선택은 실행 창별로 저장된다.

## 화면 흐름

1. 처음에는 입력 대기 블록이 있다. 하단 입력창에 작성한 내용이 블록에 미리 표시된다.
2. 전송하면 요청과 Claude 출력을 가진 메인 블록이 된다.
3. Claude가 하위 에이전트를 만들면 해당 부모 아래에 요청·출력·상태를 가진 블록이 연결된다. 같은 부모의 에이전트는 좌우로 분기하며 중첩 위임도 연결한다. 백그라운드로 실행한 명령(`run_in_background`)도 같은 방식으로 **백그라운드 작업** 블록이 되어 명령과 시작 응답을 보여주고, Claude Code의 작업 완료 알림을 받으면 완료·실패·중단 상태와 요약으로 갱신된다. 알림 전에 실행이 끝나면 중단으로 표시한다.
4. 메인과 하위 에이전트가 모두 종료되면 결과 블록이 연결된다. 실제 최종 응답은 메인 블록과 결과 블록에서 모두 볼 수 있다. 실패·중단은 그 상태대로 표시한다.
5. 다음 입력 대기 블록이 이어진다. 지난 요청들은 위쪽 그래프에 남는다.

### 실행 중에 보내는 요청

실행 중에도 하단 입력창은 잠기지 않는다. 입력창의 화살표 또는 Enter로 보내면 실행기에 따라 두 가지로 처리한다.

- **Claude(이 Mac)**: 텍스트를 실행 중인 Claude의 stdin으로 바로 전달한다. Claude Code는 진행 중인 도구 호출이 끝난 뒤 그 메시지를 같은 턴 안에서 읽고 반영한다. 그래프에는 메인 블록 아래에 주황색 **중간 요청** 블록이 생겨 보낸 내용을 보여주고, 다음 루트 응답이 오면 완료 상태와 그 응답으로 갱신된다. 응답 전에 실행이 끝나면 중단으로 표시한다. 기본 화면에서는 일반 사용자 메시지로 기록된다. 첨부 파일이 있거나 결과가 이미 도착해 stdin이 닫힌 뒤라면 아래의 대기열로 넘어간다.
- **Codex · Gemini · 원격 워크스페이스 · 셸**: 이 실행기들은 한 요청을 한 프로세스로 처리하므로 중간 입력을 받을 수 없다. 보낸 내용은 입력창 위 **대기 중** 목록에 순서대로 쌓이고, 현재 요청이 완료되면 첫 항목부터 자동으로 실행한다. 목록의 ✕로 항목을 지울 수 있다. 실행을 직접 중지하면 대기열도 취소되고, 오류로 끝나면 대기열은 남아 있으며 **다음 실행** 버튼으로 이어갈 수 있다. 대기열은 실행 창당 16개까지이며 앱을 다시 열면 비워진다.

### 컨텍스트 정리 블록

긴 작업 중 CLI가 스스로 대화 맥락을 요약(컴팩션)하면 그래프에 민트색 **컨텍스트 정리** 블록이 생긴다. 이미 끝난 일을 알리는 이벤트라서 블록은 도착과 동시에 완료 상태이고, 헤더의 집계에는 `컨텍스트 정리 N`으로 따로 센다. 기본 화면에는 같은 내용이 시스템 메시지 한 줄로 남는다.

| 실행기 | 신호 | 블록 내용 |
|---|---|---|
| Claude | `system` 프레임의 `subtype: compact_boundary` · `compact_metadata{trigger, pre_tokens, post_tokens, duration_ms, messages_summarized}` | `자동 정리 · 84,120 → 21,300 토큰 · 12.3초` 형식. 하위 에이전트 안에서 일어난 정리는 그 에이전트 블록 아래에 붙고 기본 화면에는 남기지 않는다. |
| Codex | `item.completed`의 `type: context_compaction` (토큰 수 없음) | `Codex가 대화 맥락을 요약했습니다.` |
| Gemini | 헤드리스 `stream-json` 출력에 압축 이벤트가 없음 (`init·message·tool_use·tool_result·error·result`뿐) | 블록 없음 |

같은 식별자의 프레임이 반복돼도 블록은 하나다.


실행 중에 텍스트가 있으면 중지 버튼은 작은 보조 버튼이 되고 화살표가 전송을 맡는다. 텍스트가 없으면 예전처럼 중지 버튼만 보인다.

블록 안에서는 기본 화면의 Markdown·도구 표시와 텍스트 선택을 사용한다. 그래프는 고정된 뷰포트 안에서 자유롭게 이동하고 확대·축소할 수 있다. 이동해도 상단 도구 모음과 하단 입력창은 제자리에 남는다.

### 스크롤과 실행 표시

- 블록 오른쪽 아래의 대각선 화살표를 드래그하면 가로·세로 크기를 조절한다. 메인·하위 에이전트·결과·입력 대기 블록 모두 지원하며, 연결선과 주변 블록도 함께 재배치된다. 크기는 세션별로 저장되어 다시 열어도 유지된다.
- 크기 조절 중 Esc를 누르면 시작 크기로 돌아간다. 모서리를 우클릭해 **기본 크기로 되돌리기**를 선택하면 저장한 크기를 초기화한다. 블록 제목줄 오른쪽의 세로 펼치기·접기 버튼은 모서리의 대각선 크기 조절 손잡이와 다른 아이콘을 쓰며, 누르면 사용자 지정 크기를 해제하고 기본 높이를 사용한다.
- 휠·트랙패드는 기본적으로 캔버스의 시점을 상하·좌우로 이동한다. 그래프의 문서 경계에 막히지 않으며 바깥 화면의 스크롤 위치는 바꾸지 않는다.
- 블록 밖의 빈 배경을 누른 채 드래그하면 캔버스가 포인터를 따라 이동한다. 블록에서 시작한 드래그는 기존 텍스트 선택 동작을 유지한다.
- 블록을 한 번 클릭해 선택하면 해당 블록의 요청·출력 내용만 스크롤한다. 선택한 블록의 헤더 위에서도 출력 내용이 스크롤되고, 내용의 끝에 도달해도 캔버스가 움직이지 않는다. 선택한 블록은 테두리와 스크롤 표시로 구분한다. 다른 블록 위에서는 캔버스가 이동한다.
- 빈 배경을 클릭하거나 그래프에 포커스가 있을 때 Esc를 누르면 선택을 해제한다. 긴 출력은 기존의 펼치기 버튼도 사용할 수 있다.
- 블록 제목줄의 **토큰** 표시는 그 블록이 실제로 쓴 토큰 합계(입력·출력·캐시 읽기·캐시 생성)다. CLI가 각 assistant 메시지에 보고한 `usage`를 블록별로 더하며, 한 메시지가 여러 이벤트로 나뉘어 와도 한 번만 센다. 결과 블록은 요청 전체(메인 + 모든 하위 블록) 합계를, 상단 도구 모음은 실행 창의 모든 요청 합계를 보여준다. 마우스를 올리면 항목별 내역이 나온다. 백그라운드 작업 블록처럼 보고가 없는 블록에는 표시하지 않는다.
- 실행 중인 메인·하위 에이전트는 움직이는 상태 막대와 흐르는 테두리를 표시한다. 대기 중인 블록은 정적인 일시정지 표시를 사용하며, 완료·실패·중단되면 움직임을 멈춘다.
- macOS의 동작 줄이기 설정을 켜면 움직임 대신 정적인 실행 표시와 강조 테두리를 사용한다.

### 링크와 말풍선

- 성공한 **최종 결과**에서 언급한 실제 워크스페이스 파일을 중복 없이 모아 결과 카드 오른쪽의 **결과에 나온 파일** 패널에 표시한다. 에이전트 중간 출력과 웹 링크는 이 목록에 넣지 않는다. 같은 파일의 줄 번호·별칭 링크는 하나로 합치며, 파일명이 같아도 아래 상대 경로로 구분할 수 있다.
- 파일이 있는 최신 결과가 나오면 목록이 자동으로 열린다. 결과 카드 제목줄의 펼치기 버튼 옆 **파일 목록** 버튼으로 닫거나 다시 열 수 있고, 한 그래프에는 한 목록만 열린다. 직접 닫은 목록은 새 결과가 나오기 전까지 다시 자동으로 열리지 않는다.
- 목록은 결과 카드 옆에 붙어 캔버스 이동·확대·축소를 함께 따르며, 결과 카드의 크기를 바꾸면 위치와 높이도 맞춰진다. 파일이 많으면 목록 안에서 스크롤한다. 파일을 클릭하면 아래와 같은 기존 미리보기 말풍선을 연다.

- 블록 안의 파일 경로(`docs/mighty-mode.md`, `artifacts/reports/graph.html`, `/절대/경로.md`, `src/App.tsx:42`)와 Markdown의 상대 링크는 클릭할 수 있는 링크가 된다. `https://` 주소는 기본 브라우저로 연다.
- 경로를 클릭하면 다이어그램 오른쪽에 꼬리가 달린 **말풍선**이 열려 내용을 보여준다. Markdown은 렌더링해서, HTML(예: 생성한 다이어그램)은 내장 웹 뷰로, 이미지는 그대로, 그 밖의 텍스트는 고정폭으로 표시한다. 말풍선의 버튼으로 왼쪽·오른쪽 위치를 바꾸고, Finder에서 보거나 기본 앱으로 열 수 있다. Esc 또는 닫기 버튼으로 닫는다. 블록과 같은 방식으로, 다이어그램을 향한 아래 모서리의 대각선 손잡이를 끌면 너비와 높이를 함께 조절하고 두 번 클릭하면 기본 크기로 돌아간다. 크기는 앱 전체에서 기억된다.
- 경로는 현재 워크스페이스 폴더 안의 실제 파일로만 해석한다. 폴더 밖을 가리키거나(`..`, 절대 경로, 심볼릭 링크 포함) 없는 파일이면 말풍선에 그 이유를 표시하고 아무것도 읽지 않는다. 2 MiB보다 큰 파일과 텍스트가 아닌 파일은 기본 앱으로 열도록 안내한다. 원격 워크스페이스에서는 링크를 만들지 않는다.
- 링크는 마이티 모드에서만 만들어지며 기본 화면의 대화 표시는 바뀌지 않는다.

## 플러그인

마이티 모드를 선택하면 Claude·Codex 창 상단의 퍼즐 아이콘에서 설치된 플러그인을 확인하고, CLI가 제공하는 마켓플레이스의 플러그인을 검색·설치할 수 있다. 설치 범위와 지원 사항은 [플러그인 관리](claude-plugins.md)를 참고한다.

## 실행 데이터

- Claude의 구조화된 CLI 출력과 인증된 Mods 이벤트를 사용한다. 별도의 대화 로그 파일을 읽어 추측하지 않는다.
- 백그라운드 작업 블록은 CLI 스트림의 `tool_use`(`run_in_background`)와 시작 응답, 이후 사용자 턴에 주입되는 `<task-notification>`(`tool-use-id`·`task-id`·`status`·`summary`)만 사용한다. Mods에는 작업 알림 이벤트가 없으므로 출력 파일을 읽어 추측하지 않는다.
- Mods의 `agent.spawn`에서 실제 요청과 부모 에이전트를, `turn.complete`에서 해당 에이전트의 실제 최종 응답을 받는다. CLI의 `parent_tool_use_id`로 에이전트별 메시지와 도구 출력을 구분한다. 연동 계약은 [Claude Code의 공식 Mods 타입](https://github.com/anthropics/claude-code/blob/main/mods/types/claude-code.d.ts)의 2.1.273 정의로 확인했다.
- 프로세스별 ID로 요청을 구분하고 같은 에이전트의 이벤트는 갱신한다. 늦게 도착한 이벤트가 다음 요청의 블록으로 섞이지 않도록 한다.
- 새 기록에는 그래프 관계를 저장한다. 기존 기록은 사용자 요청을 기준으로 묶으며, 수집하지 않았던 과거 하위 에이전트의 관계나 요청 내용을 만들어 넣지 않는다.
- 이전 원격 호스트처럼 그래프 이벤트를 제공하지 않는 연결에서는 실제 요청과 대화 출력만 표시한다. 새 Mac 호스트·클라이언트는 `x-mighty-graph`로 확장 이벤트를 협의한다.
- 저장 파일과 실행 출력에는 기존 앱과 마찬가지로 크기 제한이 있다. 그래프는 최근 128개 요청, 요청당 최대 128개 하위 에이전트와 제한된 출력 기록을 보존한다. 대화별 메모리와 저장 프로필의 그래프 기록에는 각각 2 MiB 예산을 적용하며, 오래된 기록이나 출력이 줄어도 현재 요청의 하위 에이전트 식별과 종료 상태를 우선 보존한다. 앱이 종료된 동안 실행 중이던 블록은 복원 시 중단 상태로 표시한다.

## Codex

Codex 실행 창은 `codex exec --json`이 내보내는 JSONL을 사용한다. 실제로 전달된 하위 에이전트 작업을 기본 화면의 활동 행과 마이티 모드의 블록으로 확인할 수 있다.

- **기본 화면**: CLI가 내보내는 협업 도구 호출(`spawn_agent`·`send_input`·`wait`·`close_agent`)을 진행 상태와 함께 표시한다. 보고된 요청·대상 스레드·상태·응답을 사용하며, 에이전트 이름이나 역할이 없는 경우 작업 정보와 스레드 식별자로 구분한다.
- **메인 블록**: 요청과 루트 스레드의 대화·명령·파일 변경 활동을 표시한다. 마지막 `agent_message`가 최종 응답이며, 토큰은 각 `turn.completed`의 `usage`를 더한 값이다.
- **하위 에이전트 블록**: `collab_tool_call`의 대상 스레드별로 만들어지고 같은 스레드의 관측은 같은 블록을 갱신한다. `prompt`가 최초 요청이며, 추가 요청은 기존 요청·응답을 유지하면서 기록에 더한다. `agents_states`가 보고한 상태와 `message`로 실행·완료·중단·실패와 응답을 표시한다. 여러 대상 스레드가 보고되면 각각 별도 블록으로 표시한다.
- **후속 작업**: 성공한 새로운 `send_input`처럼 CLI가 명시적으로 확인해 준 새 활동은 완료된 블록을 다시 실행 중으로 바꿀 수 있다. 이전 활동의 늦은 상태·응답은 새 활동을 덮어쓰지 않는다. 끝난 전체 요청이나 복원된 중단 기록은 후속 이벤트로 다시 열지 않는다. 새 활동도 같은 스레드 블록에 누적된다.
- **스트림의 한계**: 하위 스레드 내부의 도구 활동·중간 출력·중첩 생성은 현재 exec 스트림에서 항상 전달되지 않는다. 전달되지 않은 작업은 표시하거나 추측하지 않는다. 최신 내부 동작인 `FollowupTask`·`SendMessage`·`Interrupt`·`ListAgents`도 exec가 내보내지 않으면 볼 수 없다. `Resume`이 `wait`로만 전달되는 경우에는 그것만으로 새 활동을 추측하지 않는다.
- 확인 기준은 Codex CLI 0.153.4와 openai/codex의 exec 이벤트 정의다. `collab_tool_call`과 이전 이름 `collab_agent_tool_call`을 허용하며, 보고되지 않은 이름·역할·시간·토큰 수를 만들어 내지 않는다. 백그라운드 명령 작업 블록은 Claude 전용이다. 플러그인 브라우저·참조 링크·말풍선·블록 크기 조절은 Claude와 Codex 모두 지원한다.

이번 화면은 네이티브 Mac의 Claude·Codex 실행 창에 적용된다. Gemini CLI 스트림에는 에이전트 구조가 없어 기본 화면만 제공한다.
