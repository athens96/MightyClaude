# Tailscale 원격 워크스페이스

Mac에서는 사이드바의 톱니바퀴 **설정 → Tailscale 원격 연결 설정**에서 아래 연결·공유 화면을 연다.

MightyClaude 두 앱을 연결하면 현재 앱에서 다른 컴퓨터의 워크스페이스를 열고 Claude Code·Codex·Gemini CLI와 명령 실행을 제어할 수 있습니다. 파일과 CLI 로그인은 실행하는 컴퓨터에 있습니다. 프로젝트 파일을 동기화하거나 로컬로 복사하지 않습니다.

## 연결하기

1. 두 컴퓨터에 MightyClaude와 [Tailscale](https://tailscale.com/docs/how-to/quickstart)을 설치하고 같은 tailnet 또는 허용된 공유 관계로 연결합니다. 실행할 컴퓨터에 사용할 CLI를 설치하고 로그인합니다.
2. 실행할 컴퓨터의 MightyClaude에서 로컬 프로젝트 폴더를 엽니다.
3. **원격 연결 → 이 컴퓨터 공유**에서 공유할 워크스페이스를 선택하고 **공유 시작**을 누릅니다. 기본 포트는 `43137`입니다.
4. 제어할 컴퓨터에서 **원격 연결 → 다른 컴퓨터 연결**에 호스트의 주소와 연결 키를 입력합니다. Tailscale IP 또는 해당 기기의 MagicDNS 이름을 사용할 수 있습니다.
5. 연결된 컴퓨터의 워크스페이스를 **열기**로 가져옵니다. 실행 창에서 프로바이더와 모델을 선택하고 요청을 보냅니다. 표시되는 모델과 설치 상태는 원격 컴퓨터의 정보입니다.

Tailnet 정책과 운영체제 방화벽에서 상대 기기가 해당 포트에 접근할 수 있어야 합니다. 주소는 호스트 앱이 보여주는 값을 사용하세요. Tailscale Serve·Funnel이나 공유기 포트 포워딩은 필요하지 않습니다.

## 실행과 연결 종료

- 원격 창의 **실행 중지**는 호스트의 해당 프로세스를 중지합니다.
- **연결 해제**는 해당 연결의 작업을 중지하고 연결 정보를 남깁니다. 다시 연결하려면 **새로고침**을 사용합니다.
- 네트워크가 끊어지면 클라이언트는 연결 오류를 표시합니다. 호스트는 클라이언트의 확인이 오지 않는 작업을 약 30초 안에 중지합니다.
- 호스트의 **공유 중지**는 원격 실행을 중지하고 연결 키를 폐기합니다. 공유를 다시 켜면 새 키를 사용해야 합니다. 같은 주소로 새 키를 입력하면 기존 연결을 갱신합니다.
- 앱을 다시 열면 공유는 꺼진 상태로 시작합니다. 원격 컴퓨터가 잠들거나 MightyClaude가 종료되면 새 작업을 실행할 수 없습니다.

## 연결 범위와 저장

서버는 활성 Tailscale 주소에만 바인딩합니다. 연결 키는 모든 요청에서 확인하고, 호스트에서 선택한 로컬 워크스페이스만 실행할 수 있습니다. 클라이언트는 대상 주소를 확인한 뒤 해당 IP에 연결하며 다른 주소로의 리디렉션을 따르지 않습니다. 전송은 Tailscale의 [암호화된 연결](https://tailscale.com/docs/concepts/tailscale-encryption)을 사용합니다.

연결 키를 가진 기기는 공유한 워크스페이스에서 작업과 명령을 실행할 수 있습니다. 연결 키는 신뢰하는 기기에만 전달하세요. 호스트의 CLI 계정이 사용되므로 사용량도 해당 계정에 기록됩니다.

하단 입력창에서 선택한 권한·Fast 모드·추가 설정은 원격 실행에도 적용됩니다. 호스트가 지원하지 않는 옵션을 선택하면 실행 전에 오류를 표시하므로 두 앱을 함께 업데이트하세요. 공유 폴더 목록은 작업을 시작할 위치를 제한합니다. 파일 접근을 격리하는 경계는 아니며, 전체 접근 모드나 명령 창은 호스트 사용자 권한으로 폴더 밖에도 접근할 수 있습니다.

입력창에 첨부한 파일·이미지는 내용 자체가 원격 컴퓨터로 전송됩니다. 로컬 파일 경로를 원격 컴퓨터에서 열려고 하지 않습니다. 한 번에 최대 8개, 파일당 5 MiB, 합계 8 MiB까지 보낼 수 있으며 두 앱 모두 첨부 기능을 지원해야 합니다. 실행에 쓰인 임시 사본은 작업이 끝나면 삭제됩니다. 이후 요청에서 같은 파일을 다시 읽어야 한다면 다시 첨부하세요. CLI가 생성한 결과 파일이나 CLI 자체의 대화 기록은 해당 CLI와 작업의 동작에 따릅니다.

네이티브 클라이언트의 연결 키는 macOS Keychain 또는 Windows DPAPI로 보호합니다. Mac 앱은 저장된 연결 키를 앱 시작 시 읽지 않고, 그 연결을 **새로고침**할 때 처음 읽습니다. 로컬 개발 빌드는 ad-hoc 서명이라 빌드마다 다른 앱으로 취급되어 macOS가 Keychain 접근을 다시 묻습니다. Keychain Access의 인증서 지원에서 "코드 서명" 유형의 로컬 인증서를 만들고 `MIGHTY_CODESIGN_IDENTITY="<인증서 이름>" bash scripts/build-macos.sh`로 빌드하면 "항상 허용" 선택이 이후 빌드에도 유지됩니다. 안전한 저장을 사용할 수 없으면 현재 앱 실행 중에만 유지합니다. 워크스페이스 기록에는 연결 키를 넣지 않습니다. 기존 Electron 앱에서 사용한 키는 네이티브 앱에서 다시 입력해야 합니다.

## 구현 경계

- 앱 간 프로토콜은 인증된 HTTP 요청과 실행별 출력 커서를 사용합니다.
- 원격 작업마다 별도 실행 ID를 부여해 로컬 창과 다른 원격 작업을 구분합니다.
- 공유 워크스페이스, 요청 크기, 로그 버퍼, 실행 수와 연결 시간을 제한합니다.
- 테스트의 루프백 주소 허용은 코드에서 주입하는 테스트 옵션이며 앱의 IPC나 연결 입력으로 활성화할 수 없습니다.
- Tailscale 설치·로그인·tailnet 정책은 앱 밖에서 관리합니다.
